MyCodex 用户手册

本手册介绍当前版本的主要入口、办公模式、自动化、在线更新、认证中心、统一会话历史、目标、手机连接与配对、无障碍操作、独立会话窗口、附件和文件管理、子代理管理、消息查看、导入与同步、扩展管理和目标选项。

一、开始前你需要知道

MyCodex 默认使用随程序一起提供的 Codex 运行时，正常情况下启动后即可使用，不需要手工下载 Codex CLI。

通过 设置 -> 目标 打开或激活已配置目标，各目标拥有独立窗口。需要配置时打开 目标管理器...，编辑 本机 的 Windows 运行时方式，或新增 WSL、SSH 目标：

  • 内置：默认选项，使用随 MyCodex 打包的 Windows Codex 运行时。
  • 系统：使用 Windows 系统路径中已经安装好的 codex。
  • 自定义：手动指定一个本地 codex.exe 或 codex.cmd。
  • WSL：保留 Windows 图形界面，在 WSL 发行版中运行 Codex。
  • 远程 Unix（SSH）：保留 Windows 图形界面，通过 SSH 在远端 macOS 或 Linux 主机上运行 Codex。

WSL 模式适合希望用 Linux 工具链处理项目，或希望减少中文文件在 Windows 命令环境中发生编码误读的用户。MyCodex 不会自动安装 WSL 或 WSL 内的 Codex；使用前需要你先准备好 WSL 发行版，并确保其中可以执行 Codex。

如果你之前已经在以下任一环境里登录过：

  • Codex CLI
  • 官方 App

每个执行目标都使用自己的 Codex 登录、配置和历史。Windows、每个 WSL 发行版和每个远程 SSH 目标彼此独立，MyCodex 不会在这些目标之间复制登录或配置。

通过其他工具修改 Codex 配置后，新配置会在下次启动目标时生效。Windows 目标也可以使用 文件 -> 重载目标 立即应用；普通自动重连不会应用这些变更。

二、第一次使用怎么开始

  1. 启动 MyCodex。
  2. 一般不需要处理运行时设置；程序会默认使用内置 Codex 运行时。
  3. 如果你要使用 WSL，进入 设置 -> 目标 -> 目标管理器...，选择 新增 WSL，检测并保存，再从目标菜单打开。
  4. Windows 目标需要登录时会自动打开 认证中心。点击 添加，选择 ChatGPT 账号并完成浏览器或设备代码登录，也可使用已保存账号；保存配置后，在列表中按 Enter 或右键选择 启用。
  5. 使用 API 时，可在认证中心添加官方或第三方配置，填写地址、密钥和模型后保存并启用。认证后台会保存配置及所需凭据，便于以后切换，请妥善保护目标数据。
  6. WSL 或 SSH 目标需要官方登录时仍会显示登录引导，支持浏览器、设备代码或 API Key；也可从 账户 -> 认证中心… 管理该环境的配置。浏览器无法回调时可改用设备代码。
  7. 如果当前目标已经配置了可用的第三方模型服务，即使没有 ChatGPT 账户也可以正常使用，MyCodex 不会重复要求登录。
  8. 回到 MyCodex 后，点击 新建工作区。
  9. 选择你的项目目录。
  10. 如果当前工作区下还没有会话，可以点击 新建会话；也可以直接输入内容后发送，程序会自动创建新会话。
  11. 按 Alt+I 跳到输入框。
  12. 输入你的需求。
  13. 按 Ctrl+Enter 发送。
补充说明：
  • 如果程序提示“请先打开工作区”，说明当前还没有选定项目目录。
  • 如果程序提示“当前工作区下暂无会话”，这是正常状态，可以新建会话或直接发送消息自动创建。
  • 如果旧会话暂时无法继续，请按界面提示刷新或重试。

三、先认识主界面

主界面主要分成三块：

  • 左侧：工作区和会话。
  • 中间：消息列表、输入区、待发送项目。
  • 右侧：活动区和终端入口。

右侧“活动”区域显示当前任务的进度和重要状态，例如计划、推理摘要、工具调用、网络请求和文件变更。任务结束时，如果当前目标提供了用量信息，完成提示也会显示本轮和累计用量。命令的详细输出请在独立终端窗口中查看。

活动区右键可以切换 显示日志。关闭后仍保留摘要，只隐藏日志段；如果只想清理已有日志，可以右键选择 清空日志。

终端 按钮用于打开独立命令终端窗口。终端窗口即使当前没有命令也可以打开，底部提供标准输入框；输入命令后按回车即可执行，例如 ping 127.0.0.1、git status 或项目构建脚本。

命令执行会跟随当前运行目标：Windows 使用 Windows 命令环境，WSL 使用其中配置的 Linux shell，远程 Unix 使用远端主机上的 shell。

终端会保存当前命令及其输出；后台命令产生新输出时，不会自动弹出窗口或抢占焦点。

四、最常用的几个操作

1. 发送消息

  • Alt+I：跳到输入框。
  • Ctrl+Enter：默认发送消息，Enter 默认换行。

在 设置 -> 选项... -> 界面 中，可通过 发送消息快捷键 交换 Enter 与 Ctrl+Enter 的作用，并选择工作期间的补充消息采用 引导 或 排队。

Codex 发起异步补充问题时，待回答问题 窗口可以选择建议答案，也可以选择 其他（自行输入） 后输入内容。选择“其他”后必须填写非空答案才能发送；预选选项不会自动提交。使用 稍后回答 可暂时收起窗口，未提交的答案会保留。

2. 计划模式

计划模式适合先让 Codex 给出实施计划，再由你确认是否进入执行。它是当前会话级开关，不会影响其他会话。

  • 在消息列表中打开右键菜单，选择 计划模式，即可为当前会话启用或关闭。
  • 也可以在输入框直接发送 /plan 来启用计划模式，或发送 /plan 你的需求 直接请求一份计划。
  • 计划生成后，MyCodex 会询问是否执行该计划；选择执行后会自动切回普通执行模式并发送执行提示。
  • 当前会话是否启用计划模式，以消息列表右键菜单中的 计划模式 勾选状态为准。

3. 新建工作区和会话

  • 新建工作区：选择一个项目目录作为当前工作区。
  • 新建会话：在当前工作区下创建新的对话。

如果当前工作区下还没有会话，直接在输入框中输入内容并发送，也会自动创建新的会话。

3.1 办公模式

编程 和 办公 是同一个主窗口中的两个无障碍标签页。办公模式面向 Word、Excel、PowerPoint 等日常文件工作，编程模式保留面向项目的工作流程。默认启动模式只决定 MyCodex 启动后聚焦哪个标签页，不会禁用另一个标签页。

  • 可以直接选择标签页，按 Ctrl+1 切到编程、按 Ctrl+2 切到办公，使用 Ctrl+Tab/Ctrl+Shift+Tab 前后切换，或使用 文件 菜单中的动态模式命令。
  • 切换标签页只改变当前显示的内容；另一个标签页中的响应、命令、独立工作台和自动化会继续运行。
  • 办公模式跟随当前 Windows、WSL 或远程 Unix（SSH）运行时。Windows 默认使用 文档\MyCodex-office，WSL 和 SSH 目标默认使用 $HOME/MyCodex-office。
  • 打开 设置 -> 选项... -> 办公 可查看当前运行时，并且只修改该目标的办公目录。Windows、每个 WSL 发行版和每个 SSH 配置分别保存设置与办公状态。
  • 每个运行目标都有自己的办公工作区。左侧直接显示办公会话列表；办公目录中的子文件夹只是普通文件夹，不会变成其他工作区。
  • 除非明确指定其他位置，生成的文档、表格、演示文稿、图片和配套文件都会保存到当前办公目录。
  • 清晰、低风险的日常办公请求会直接开始。MyCodex 会使用当前已经启用并适合任务的技能、插件、MCP 或命令行工具，不要求安装某个固定的 Office 插件或 OfficeCLI。
  • 编辑已有文件前会先读取或检查原文件。未明确要求覆盖时，默认创建编辑后的副本并保留原文件；明确要求覆盖、替换或保存回原文件时，该请求本身就是授权，不会重复询问同一项确认。生成或修改 DOCX、XLSX、PPTX 后会尽可能检查文件有效性和关键内容，再报告最终文件名与路径。
  • 修改办公目录不会丢失原有办公会话，也不会移动、复制、合并或删除旧目录中的文件；后续工作和交付会使用新目录。
  • 如果 WSL 或 SSH 主目录暂时无法解析，办公标签页仍然可用并会报告目录不可用。MyCodex 会保留办公工作区、会话和草稿，也不会回退到 Windows 路径。
  • OfficeCLI 引导属于可选的本地 Windows 集成，只在 Windows 运行时下提供，绝不会决定办公标签页是否可用，也不是完成办公任务的必备条件。

删除办公会话时，MyCodex 默认同步删除本地历史记录，避免旧办公任务长期堆积。删除前请确认该会话不再需要继续。

3.2 自动化

自动化 用于保存一段可重复执行的 Codex 指令，并让 MyCodex 手动或按时间计划运行它。它适合抓取新闻、定期审阅项目、检查工作区、生成 Office 报告等周期性任务。

  • 点击顶部 自动化 菜单可打开独立的自动化窗口。该窗口不会阻塞主窗口，打开后仍可继续聊天、切换会话或处理其他任务。
  • 编程和办公会话都可以在会话列表右键菜单中选择 创建自动化，让自动化以后从同一条对话继续工作。
  • 在编程模式下，工作区列表右键菜单提供 创建项目自动化...，用于把自动化绑定到当前项目工作区。
  • 新建或编辑自动化时，需要设置名称、类型、调度、模型、推理强度、审批权限和持久提示词。可以通过 插件 和 技能 按钮插入结构化的插件或技能引用。
  • 可选调度包括仅手动、每隔几分钟、每隔几小时、每天和每周；目前不支持完整 cron 表达式或工作树自动化。
  • 新建自动化默认处于启用状态。在 自动化 标签页中，可右键某条自动化执行编辑、启用、禁用或删除；选中自动化后点击 立即运行 可立刻启动一次运行。

自动化窗口包含两个标签页：

  • 自动化：显示已保存的自动化定义、类型、启用状态和下一次运行时间。
  • 运行结果：显示每一次运行记录，包括运行中、已完成、失败、已取消、已跳过、等待审批和等待输入等状态。

在运行结果列表中，可按 Enter、双击或点击 详情 打开只读运行记录。该窗口上方显示名称、状态、开始时间、完成时间、模型和工作区路径，中间是本次运行关联会话的 消息 列表和 活动 列表，底部提供 刷新、在主窗体打开会话、打开工作区 和 关闭。详情窗口只用于查看，不提供输入框、附件或继续对话能力。

运行结果可以打开、在仍然运行时停止，也可以从本地自动化结果列表中删除。删除运行结果时，会出现与主窗体删除会话类似的确认窗口；如果该运行有关联本地会话记录，可勾选同时删除本地历史记录。删除某条自动化时，也会删除它对应的本地运行结果。

自动化结果及需要关注的事项可在自动化窗口的 运行结果 标签页查看。任务状态保留在 MyCodex 中，不额外弹出桌面通知。

自动化的模型和推理强度选项来自当前目标。未指定模型时，MyCodex 会使用当前可用的默认模型；已保存模型不再可用时，本次运行会选择当前可用模型，并在运行记录中显示“配置模型”和“实际模型”。自动化仍遵守所选审批权限，不会绕过权限确认。

常用键盘操作：F5 刷新自动化窗口，Esc 关闭自动化相关窗口，Enter 打开选中的运行结果详情。

4. 编辑会话标题

  • 左侧会话列表中选中目标会话后，右键选择 编辑标题...

在 MyCodex 中修改标题会更新对应的 Codex 会话。如果同一会话在 Codex 官方应用或其他客户端中被改名，MyCodex 会在后续同步时显示新标题。标题变化只更新现有会话，不会复制或新建另一条会话。

会话级操作都在左侧会话列表的右键菜单中。

4.1 对话统计

左侧会话列表中选中目标会话后，右键选择 对话统计...，可查看标题、模型、推理强度、创建时间、最后活动时间和用量等信息。较早的历史会话或当前目标没有提供用量时，窗口会明确显示“此对话暂时没有可用数据”。

4.2 子代理会话

当 Codex 在主会话中分配子代理协同工作时，MyCodex 会把这些子代理从主会话列表中收起，避免和普通主线会话混在一起。带有子代理的主会话会在左侧会话列表项前显示或朗读类似 有 3 个子代理 的提示。

查看和操作子代理：

  • 在左侧会话列表中选中对应主会话，右键选择 查看子代理...。
  • 主会话获得线程 ID 后即可打开 查看子代理...，尚未发现代理时也可打开并刷新。
  • 子代理会在独立窗口中打开，不会切换或污染主窗口当前会话。你可以在主窗口和子代理窗口之间来回切换。

子代理窗口左侧是子代理列表，右侧是当前子代理的消息和输入区。查看不会恢复线程或修改代理配置；补充消息沿用原线程和配置，运行中的轮次接收引导输入。代理未加载或状态无法核实时，请让父代理恢复它，再刷新。窗口内切换代理时分别保留草稿。常用操作：

  • 在子代理列表中按 Enter 或双击，可打开当前子代理的消息。
  • 输入区支持 Ctrl+Enter 发送，也可以使用 发送 和 停止 按钮。
  • 插入 支持图片、文件、文件夹和技能；输入框中也可以用 Ctrl+V 粘贴图片或文件。
  • 添加附件后会出现 待发送项目 列表。选中项目按 Delete 可移除，也可以打开右键菜单移除当前项或清空全部项目。
  • 在子代理列表中按 Delete 可删除当前子代理，按 Ctrl+Delete 可删除全部子代理；右键菜单中也提供 删除 和 删除全部。
  • 删除会核对并确认当前代理及全部后代（包括已归档后代）的实际范围；运行中或状态无法核实的线程不能删除。删除无法撤销，部分失败时已确认成功的删除仍然保留。
  • Esc 会关闭子代理窗口，不会停止代理。

子代理窗口同样按键盘和读屏优先设计。焦点可以在子代理列表、消息列表、输入框、待发送项目和按钮之间移动；列表显示全部后代的名称、角色、标题、线程状态、代理报告状态、最近工作、更新时间和父线程。每 5 秒只读刷新，按 F5 可立即刷新；右键“查看最近工作”可阅读完整内容。

4.3 在独立窗口中打开会话

编程和办公会话都可以在独立窗口中打开。当你需要同时处理多个会话，又不想切换主窗口当前会话时，可以在左侧会话列表中选中目标会话，打开右键菜单并选择 在新窗口打开。焦点位于会话列表时，按 Ctrl+Enter 也可以打开选中的会话。

独立窗口是该会话的精简工作界面，包含消息列表、输入框、插入和发送、活动列表、终端、Git 工作台、文件浏览，以及有子代理时的子代理入口。窗口标题由工作区名称和会话标题组成；会话工作期间，窗口标题会同步显示工作状态。

  • 独立会话窗口不是第三种交互模式。它会保留该会话原有的编程或办公模式、工作区和运行时；再次打开同一个会话时会激活已有窗口，不会创建重复窗口。
  • 独立窗口不会阻塞主窗口；同一会话在独立窗口中发送消息或收到模型回复时，主窗口和独立窗口都会继续刷新。
  • 窗口中的终端、文件浏览和 Git 工作台始终使用该会话对应的工作区和当前运行时，对 WSL 和远程 Unix（SSH）工作区同样适用。
  • Ctrl+W 始终可以关闭独立窗口。默认启用 允许使用 Esc 关闭主窗口和独立窗口：此时 Esc 会关闭独立窗口，并会在主窗口中把它隐藏到系统托盘。如果不希望这两种窗口响应 Esc，可在 设置 -> 选项... -> 界面 中关闭该选项。
  • 正常关闭会保存尚未发送的草稿。重新打开同一会话时会恢复草稿；在同一次目标运行期间，如果对应消息仍存在，还会恢复消息列表选中项和手动 Alt 浏览位置。这些位置属于原窗口，打开其他目标不会改变它们。

5. 打开终端

  • Alt+K：打开或激活终端窗口。

终端窗口可以直接输入系统命令、构建脚本、测试命令或 Git 命令。预设命令可从终端中的 常用命令 窗口选择。

当前最常用的内置命令通常有：

  • 构建发布
  • Git 改动

常用命令预设会按目标平台区分。只适合 Windows 的命令不会在 WSL 模式下默认混用；需要两边都能使用的命令，可以保存为同时适用于 Windows 和 WSL。选中常用命令后，可以插入到终端输入框，也可以在当前没有活动命令时直接执行。

5.1 Git 工作台

主界面的 Git 工作台 会打开独立的 Git 工作台。它不会阻塞主窗口，适合在 Codex 修改代码后检查、提交、拉取、推送和查看当前工作区状态。

  • 文件列表会按 已暂存、未暂存、未跟踪、冲突 分组显示。
  • 选中文件只会更新差异内容，不会执行 Git 写操作。焦点切到差异文本框时，如果当前文件的差异尚未加载，程序可以自动补载一次。
  • 文件级操作放在文件列表右键菜单中，包括 暂存、取消暂存、丢弃未暂存改动、删除未跟踪文件、打开文件、复制路径、复制 Diff。
  • 底部可输入提交标题和详细说明，并执行 提交、获取远端、拉取、推送。没有 upstream 时，推送会提示是否设置 upstream 后再推送；也可以在远端管理中主动设置或取消当前分支 upstream。
  • 远端 管理可查看当前仓库 remote，新增远程、修改 URL、删除 remote、复制 remote 名称或 URL，并在发布当前仓库时选择远端名称和是否立即推送。
  • 分支和提交 会把分支导航和提交历史合并在同一窗体中。分支树会展示本地和远端分支，可在选中分支后按 Enter 或使用右键菜单加载该分支历史。
  • 分支树右键菜单会按当前选中对象动态显示相关动作。可切换本地分支、从远端分支创建本地跟踪分支并切换、新建分支、删除或强制删除本地分支、删除远端分支、重命名分支、比较分支 ahead/behind、查看差异提交，并刷新分支或加载选中分支历史。
  • 提交历史右键菜单可复制提交 ID、反向提交、从其他分支拣选提交、修补最后一次提交，或回滚到指定提交。与提交历史有关的高风险操作统一放在历史窗口中，不放在 Git 工作台主界面。
  • merge、rebase、cherry-pick 等进行中状态会在 Git 工作台中显示；有未提交改动、冲突或未完成 Git 操作时，切换、删除、merge、rebase 等风险操作会提示或阻止。
  • 贮藏 可保存、应用、弹出和删除 stash。加载详情后可查看文件列表和完整 diff；在文件列表按 Enter 或使用右键菜单可查看单文件 diff，并可复制当前 diff。
  • 左侧工作树树视图可查看当前仓库的 Git Worktree。选中工作树后可通过右键菜单创建新工作树、移除工作树、清理失效记录、复制路径，并把 MyCodex 当前工作区切换到另一个工作树。
  • 诊断与维护 使用同一个窗体。诊断 标签页是只读检查，会列出 Git 可用性、仓库、远端、上游、HEAD、未完成操作、工作树状态、对象数据库和锁文件等项目，并在详情中给出建议；维护 标签页提供仓库完整性检查和 Git 官方维护，检查完整性 执行只读 git fsck --full，运行维护 执行 git maintenance run，执行前会二次确认。
  • 存在冲突时会禁止提交和推送，可通过冲突文件右键菜单查看冲突详情。
  • 如果当前文件夹还不是 Git 仓库，可直接在 Git 工作台中执行 初始化仓库。

创建 Git Worktree 时，MyCodex 会建议一个同级目录，通常使用当前工作区名称加 -Worktree。你可以在确认前修改位置。

Git Worktree 在 Git 工作台中管理。

Windows 安装包自带 Git，本地 Git 工作台、克隆和环境检查优先使用它，无需另行安装全局 Git，也不会修改用户或系统 PATH。WSL 和远程 Unix 仍使用所属环境的 Git。登录凭据、SSH 密钥和 credential helper 需在相应环境中配置，程序不会代为登录。

较长的 Git 操作会在后台继续，你可以取消等待。界面显示命令输出时会尽量隐藏网址凭据、GitHub 令牌和常见访问令牌。

丢弃文件改动、删除未跟踪文件、回滚、反向提交和强制推送都会要求再次确认。只有在确定要改写远端分支历史时才使用强制推送。

5.2 Git 远端与仓库管理

顶部新增了独立的 Git 菜单，用于处理 GitHub 相关的远端能力。这部分和只针对当前工作区的 Git 工作台分开，适合做环境检查、登录、克隆和查看远程仓库。

  • Git 环境：检查当前运行时里是否可用 git，并显示用户名、邮箱、credential helper 等关键信息。
  • 远程仓库与凭据：在同一个窗口中查看 gh 登录状态和本机 SSH 密钥。GitHub 登录使用当前环境中已有的 gh 账号。
  • 克隆仓库：支持手动输入 Git URL，也支持通过 gh 加载当前 GitHub 账号下的仓库列表。手动模式和 GitHub 模式通过选项卡分开。
  • 远程仓库：打开独立的 GitHub 仓库浏览窗体。列表可显示仓库名、轻量可见性、描述、语言、默认分支和更新时间。
  • 远程仓库列表右键菜单会按仓库状态动态显示相关动作。可创建仓库、重命名仓库、编辑描述和主页、修改可见性、归档、取消归档或删除仓库。删除仓库需要二次确认并输入完整 owner/repo；缺少删除权限时，需要按 GitHub CLI 提示授予 delete_repo scope。
  • 在远程仓库列表上按 Enter 或使用右键菜单，可以打开仓库详情。详情可直接在 MyCodex 内查看概览、发行版、议题、拉取请求、贡献者、讨论、分支和标签。
  • 仓库详情的分支页支持复制分支名和提交 SHA、打开分支网页、设置默认分支、删除远端分支，并在当前工作区 remote 指向该仓库时，从远端分支获取并切换到本地工作区。
  • 仓库详情的拉取请求页支持筛选 open、closed、merged、all，筛选我创建、指派给我或请求我评审的 PR，从当前分支创建 PR，checkout PR 到本地，打开或复制 PR URL，查看 discussion，新增评论，关闭或重新打开 PR。
  • 仓库详情的议题页支持筛选 open、closed、all，筛选指派给我或我创建的 Issue，创建 Issue，打开或复制 Issue URL，查看 discussion，新增评论，关闭或重新打开 Issue。
  • 创建仓库 已放到远程仓库窗体中。对于当前已经是 Git 仓库但还没有绑定远端的工作区，也可以从 Git 工作台引导发布当前仓库并绑定 GitHub 远端。
  • GitHub 商店：从 Git 菜单打开，使用 搜索 标签页查找指定仓库，使用 榜单 标签页浏览推荐内容。
  • 搜索 标签页支持关键词、语言、主题和结果数量，并提供明确的 搜索 按钮。许可证、Star/Fork/未关闭 Issue 范围、排序和只看公开仓库等不常用条件通过 显示高级条件 展开；修改高级条件后不会自动搜索，需要再次点击 搜索。
  • 榜单 标签页用于浏览发现项目，只保留榜单类型、语言、结果数量和 刷新榜单。榜单预设包括 Trending/New Repos/New Stars/New Forks/High Activity/Recent Created/Top Forks/Recent Updated。
  • 搜索结果列表展示仓库、描述、语言、Stars、Forks、未关闭 Issue、许可证、更新时间、推送时间、主题，并在操作后保留焦点位置，避免列表重排打断连续选取。
  • 市场列表项可通过 Enter 打开主页，也可通过右键菜单执行动态动作：打开仓库页、复制 HTTPS URL、复制全名、Clone、Fork and Clone；本地仓库已存在时可直接 Fetch/Pull 对应仓库。

GitHub 账号登录、仓库列表和托管管理需要当前环境中另行安装并登录 gh CLI，内置 Git 不包含它。没有 gh 时仍可通过手动 Git URL 克隆仓库；访问私有仓库还需要可用凭据。

SSH 在这里被视为 Git 传输方式，而不是单独的一套账号系统。你可以继续通过 gh 使用 HTTPS，也可以在把公钥配置到 GitHub 后，把远端地址切到 SSH。

6. 插入图片、文件、文件夹、插件和技能

点击输入区旁边的 插入，可以：

  • 选择图片
  • 选择文件
  • 选择文件夹
  • 选择插件
  • 选择技能

也可以在输入框中直接使用 Ctrl+V 粘贴图片或文件。

图片、文件、文件夹、插件和技能都会按当前光标位置插入。每个附件都是独立的一个对象，并单独占一行；左右方向键会把它当作一个位置移动，按 Backspace 或 Delete 会删除整个附件，而不是删除附件名称中的单个字符。该位置的朗读结果取决于读屏软件，可能朗读为“嵌入式对象”，也可能表现为空白，目前不能保证直接读出附件名称；需要可靠核对名称时，请使用待发送项目列表。

6.1 文件浏览

当前目标可浏览文件时，工作区右键菜单会提供 文件浏览...。Windows 目标显示本机路径，WSL 目标显示 WSL 中可访问的路径，远程 Unix 目标显示远端主机路径。

文件浏览使用接近 Windows 资源管理器的详细信息列表，显示名称、修改时间、类型和大小。修改时间精确到分钟；文件信息发生变化时会刷新。使用 Up / Down 浏览文件行，使用 Left / Right 浏览当前文件的列。

文件浏览窗口支持回到 Home、上级目录、刷新、搜索、新建文件夹、新建文件、预览、复制、剪切、复制路径、删除和作为附件加入待发送项目。使用 Ctrl+C 或 Ctrl+X 复制或剪切选中的项目，再在目标目录按 Ctrl+V 粘贴，即可直接整理文件。该流程同样适用于本机 Windows、WSL 和远程 Unix（SSH）文件系统；粘贴部分失败时才会提示失败数量，避免打断正常焦点朗读。地址栏可直接输入路径，搜索框可在当前路径下搜索文件；按 Esc 会先退出搜索，搜索框为空时关闭窗口。

打开文件时，明确的文本类型会进入文本查看或编辑流程；压缩包、可执行文件、图片、音频、视频等非文本类型会尽量交给 Windows 系统默认应用打开。只有 Windows 可直接访问的路径才能系统打开，例如本机路径或 WSL 的 /mnt/c、/mnt/d、/mnt/e 挂载路径。WSL 的 /home/user/... 和远程 SSH 主机上的非文本文件不会被自动下载到本机临时目录打开，以免造成“打开的是副本”或误执行远端文件的风险。

使用 附加 后，选中的文件路径会进入当前消息的待发送项目，后续发送时随问题一起提交。

7. 导入与同步

工作区相关的历史迁移入口统一放在左侧工作区列表的右键菜单 导入与同步 下：

  • 同步历史会话...：读取当前 Codex Home 下尚未进入 MyCodex 的本机历史会话，并同步到当前工作区。
  • 导入其他会话...：从其他工作区或未关联会话中选择内容，完整复制成当前工作区的新会话。它是复制导入，不会把源会话移动过来，也不会因为之后删除导入会话而删除源会话。
  • 导入外部智能体配置...：检测外部智能体配置，可按用户配置和当前工作区范围选择要导入的项目。

导入和同步窗口内常用操作：

  • F5：重新读取列表。
  • Space：勾选或取消勾选当前项。
  • Enter：执行当前勾选项目的同步或导入。
  • Esc：关闭窗口。

导入其他会话 默认不勾选列表项，需要明确选择后再导入，避免误把大量会话复制到当前工作区。外部智能体导入也必须先预览和明确勾选；宽泛配置项和未知项目不会导入，MyCodex 不会在后台自动迁移外部配置。

8. 认证中心、登录与用户中心

打开 账户 -> 认证中心…，可管理当前目标的模型服务配置和已保存账号。窗口上方显示目标和 Codex Home，操作前先确认位置。Windows、WSL 和 SSH 分别使用所属环境的数据；认证中心不会把 Windows 凭据复制到其他目标。

认证中心修改的是该 Codex Home 的全局配置，使用同一位置的 Codex CLI 或其他客户端也会受到影响。连接后会尝试识别并收录当前配置；需要查看外部配置变化时可刷新认证中心，但已运行的聊天连接仍需重载目标或正常重启才能重新读取。

  • 添加：选择预设或配置类型。支持 ChatGPT 账号、官方 OpenAI API，以及第三方 Responses、Chat Completions 和 Anthropic Messages API。按界面填写名称、API 地址和密钥；不同协议可能需要认证后台进行转换。
  • ChatGPT 配置可使用浏览器登录、设备代码登录或 使用已保存账号。登录成功先保存账号，再点击提供商窗口的 保存 完成配置；登录成功本身不会切换当前身份。
  • API 配置可使用 获取模型 或 手动添加模型，并选择默认模型。程序会尝试补全空缺的上下文长度和推理等级，保存前请核对；上下文与压缩 区域可调整当前后台支持的相关设置。
  • 列表仅选中一行不会切换。按 Enter 或右键选择 启用 才应用所选配置；双击或右键 编辑 打开配置窗口。右键还可复制、重新登录或删除非当前配置。
  • 保存新配置或未启用配置不会切换当前供应商；编辑当前配置时会读取当前全局设置，保存会立即更新这些设置并尝试重连。进行中的响应、命令、自动化等工作会阻止配置变更，请结束工作后再试。
  • 已保存账号 用于查看和删除账号。删除供应商配置后，应以结果提示确认其账号是否仍被其他配置使用；主动删除账号还可能清除匹配的全局登录，引用它的配置将需要重新登录。
  • 若提示“配置已应用，但重连失败”，请使用 重试连接；已经写入的全局配置不会自动回滚。旧会话可能需要选择兼容模型，或新建会话。

编辑提供商配置 可打开 TOML 编辑器。支持完整编辑的后台会展示切换到该提供商后的完整 config.toml；提供商字段随配置保存，其他修改在外层提供商窗口点击 保存 时写入全局文件。编辑器内保存只回填表单。若其他程序同时改了相同字段，窗口会列出冲突，供你选择保留哪一方或取消。配置文本可能含有凭据，不要直接分享。

Windows 随程序提供认证后台；WSL 和 SSH 认证中心会检查并在需要时部署对应平台的后台组件，需要网络及目标目录写入权限。出现兼容性提示时，按界面使用 更新后台；本机组件缺失时可重新安装 MyCodex。配置依赖协议转换时，目标重启后应先打开 MyCodex 恢复服务，再使用同一环境中的 CLI。

8.1 统一 Codex 会话历史

认证中心中的 统一 Codex 会话历史 默认关闭，只影响当前执行目标。开启后，ChatGPT 账号和第三方供应商使用共享会话标识，旧会话可在切换后使用当前配置继续。

  • 切换前先关闭其他 Codex 客户端，阅读确认窗口中的迁移数量。开启会迁移以前的官方会话标识，不复制对话内容；关闭开关前，官方 ChatGPT 客户端将不再列出这些会话，MyCodex 中仍可看到。
  • 关闭时会恢复以前迁移过的官方会话，保留期间新增的内容。开启期间新建的共享会话仍保留共享标识，之后只能通过第三方供应商继续，官方 ChatGPT 客户端不会列出它们。
  • 迁移或还原未完成时，使用 重试迁移会话。不要通过删除历史文件解决待迁移状态。
  • 用 ChatGPT 继续其他供应商的会话时，程序会先清理不兼容内容，例如其他供应商的推理内容。若还需要替换无法读取的旧压缩摘要，会单独询问；确认后模型将无法再看到摘要中那部分较早的对话，会话备份会保留。

8.2 用户中心与官方设置

账户 -> 用户中心 适用于 ChatGPT 账号，可查看账号、套餐、额度、速率限制和用量；未提供的信息会明确说明。只有账户支持时才能使用 重置额度，执行前会确认。

设置 -> 选项... -> 官方设置 可编辑支持的用户级 Codex 运行时设置。没有 ChatGPT 账户不一定表示错误，可用的第三方配置也能正常工作。通过外部工具修改登录或模型配置后，请正常重启目标；Windows 目标也可使用 文件 -> 重载目标。普通自动重连不会重新读取这些外部变更。

9. 检查更新

MyCodex 启动后会自动静默检查更新；如果发现新版本，会弹出更新窗口并显示与当前界面语言匹配的升级日志。

  • 也可以手动打开 帮助 -> 检查更新...。
  • 更新窗口中的升级日志是标准文本框，打开后会默认聚焦，适合读屏直接阅读。
  • 选择 立即更新 后会显示下载进度；下载完成后先核对运行目标，再确认 退出全部并安装更新。全部列出的目标保存并同意后才开始退出；安装器等待所有受影响进程实际结束。取消或仍有无法核验退出的进程时，不启动安装。
  • 同一安装目录只允许一次更新。其他版本若正在使用该目录的文件，需要先正常退出，不会被静默关闭。开发版窗口会提示构建并替换开发版，而不会运行正式版安装器。
  • 选择 忽略更新 会跳过当前检测到的版本；后续更高版本仍会提示。

10. 手机连接与配对

在要访问的目标窗口中打开 设置 -> 手机连接...。各目标分别启用手机连接、保留独立身份和设备访问权限；所有目标共用一份服务地址和端口。

  • 通过窗口内的 连接设置... 选择内置服务或公网服务。这里的设置适用于所有目标；应用前会列出受影响目标，手机连接可能短暂重连，桌面任务继续。
  • 选择 生成配对码 后，配对信息会复制到剪贴板。在手机端导入后，应核对手机与 Windows 端显示的六位验证码；一致时选择 允许，不认识的请求选择 拒绝，需要稍后从设备列表处理时选择 稍后处理。
  • 需要时刷新已配对设备列表。右键菜单可处理待确认的请求，或移除设备并撤销其对本目标的访问。停用 A 的手机连接不影响 B。
  • 使用公网服务时，在连接设置中通过 导入服务器信息 导入完整部署 JSON，或手动填写连接参数，检测后应用。不要向他人泄露访问密钥。
  • 手机将各目标分别添加为设备，同时只连接、监控一个目标。浏览设备详情不会切换，需明确选择 检查并连接。未运行的目标不可用，手机不能启动它。
  • 切换先保存各设备的编程、办公草稿及页面，断开原连接后再连接新设备；原目标的桌面任务继续。失败或取消会尝试恢复原连接，切回后重新读取历史和待处理请求。
  • 普通升级、改名和重启保留原配对；新增目标才需要首次配对。手机版 当前设备设置 可修改该目标的默认模型、权限及支持的 Codex 高级设置。

列表行只显示简短预览。长日志或代码的预览可能以省略号结尾，但原文不会因此截断：读屏可访问文本、复制、手动朗读和消息查看器仍使用完整内容。按 Enter 可查看整条消息；浏览已选消息时，没有变化的刷新会保留选择和浏览位置。

  • Home / End：移动到第一条或最后一条消息。

  • Right：跳到下一轮用户提问。

  • Ctrl+F：打开“查找消息”。
  • F3：查找下一个匹配。
  • Shift+F3：查找上一个匹配。

  • Enter：当焦点在消息列表时，打开当前消息查看器。

  • 在链接上按 Enter：用系统默认浏览器打开链接。
  • 在“复制第 N 段代码”这一行按 Enter：复制对应代码块。
  • 光标已经在代码块正文里时按 Enter：复制当前代码块。

适合会话过长、想整理上下文后继续工作时使用。

入口：

  • 消息列表右键选择 压缩上下文

  • 官方设置 页面用于修改支持的用户级 Codex 配置，保存前会要求确认；选择“跟随默认”会移除对应的用户覆盖。
  • 自定义权限 按目标保存，默认权限或会话权限选择 自定义 后生效。可勾选的类别包括 Git 查看、暂存、本地提交、初始化仓库、配置变更、工作区变更、远端读取、远端写入、危险操作，构建、测试、依赖安装、通用命令，文件读取、新建、写入或修改、删除、移动或重命名、混合或未知文件变更，以及额外读取目录、额外写入目录、网络访问、混合权限请求和未知请求。
  • 自定义命令前缀 用于放行固定开头的常用命令，例如 git status 或 npm test。它按命令开头匹配，不是关键词匹配。建议只添加明确、稳定、风险可控的前缀，不要把删除、清理、强制重置或宽泛 Shell 命令加入自动允许列表。
  • 审批请求会按顺序弹出：同一时间只显示一个审批窗口，后续请求会排队等待。审批摘要会尽量用更短的命令提示和文件变更摘要说明请求内容；移动端远程审批显示同一组决定按钮，但不会显示 Windows 桌面按钮助记符。
  • 当 MCP 服务请求补充输入时，当前工具调用会等待明确答复。MyCodex 会针对选项或文本问题打开 MCP 请求 窗口，针对确认请求打开是/否对话框，针对 URL 请求先询问是否打开浏览器页面。提交答案后继续，选择取消则拒绝本次请求；如果只停留在状态提示而未处理，请求会继续等待。
  • 目标 菜单打开或激活目标，目标管理器 配置本机、新增及编辑 WSL/SSH。打开工作区 跟随本窗口目标；WSL 和 SSH 使用所属环境的绝对路径。
  • 编程和办公模式都跟随当前 App Server 运行时。办公目录覆盖和保留的办公状态按 Windows 目标、WSL 发行版或远程 Unix SSH 配置隔离；选项中的办公页面只编辑当前活动目标。
  • 默认模型、默认权限等会话偏好按当前执行目标隔离；当前会话也可在会话右键菜单中单独设置 模型、权限，或使用 重置为默认值 回到目标默认值。列表只显示当前目标可用的模型和推理等级；已保存模型不可用时会阻止发送，直到重新选择。
  • 扩展 是二级菜单，集中放置 Plugin、Skill 和 MCP 入口，让顶部菜单保持简洁。
  • 插件管理 分为 已安装 和 市场 两个标签页。市场 用于浏览、搜索和安装 Plugin；已安装 用于查看、启用、禁用、卸载或打开授权页面。
  • 插件管理 中包含 MyCodex 官方市场，可直接浏览和安装 Plugin。其他第三方市场也可在同一窗口中按提示添加；添加市场不会自动安装其中的 Plugin。
  • 安装或卸载完成后，列表会自动刷新；如果外部工具刚刚改变了 Plugin，按 刷新 重新读取。市场中能看到某个 Plugin 不等于已经安装，请以 已安装 标签页为准。
  • 如果 Plugin 提供应用连接页面，可在 已安装 标签页中使用 打开授权。打开网页本身不代表已经授权成功，还需要在网页中完成“管理”或“连接”流程；如果已经没有待处理的授权条目，Plugin 也可能已经连接。
  • 技能管理 显示当前目标可用的 Skill，不包含独立 Skill 市场。用户和项目 Skill 可以新增、编辑或删除；Plugin、系统和管理员来源保持只读。Plugin 内的 Skill 跟随所属 Plugin 的安装、启用和卸载。
  • MCP 管理 可按状态筛选，查看详情、OAuth、工具和资源，并按按钮执行新增、设置、登录、启用、禁用和删除。配置在其他工具中发生变化后，请重新刷新或重载目标。

界面 页面还提供 界面字号（重启后生效），可选 100%、125% 或 150%；保存后正常重启该目标窗口生效。会话信息展示顺序 可选“代理数量，时间，标题”“标题，时间，代理数量”或“标题，代理数量，时间”，调整每条会话的展示和朗读顺序，不改变会话的排序规则。

官方 Computer Use

本机 Windows x64 安装包自带经过校验的官方 Computer Use 执行组件和配套插件，不需要另行安装或运行官方桌面客户端。组件位于程序旁的 runtime\cua，启用状态可在 设置 -> 扩展 -> 插件管理... 中检查；明确禁用的插件不会被自动重新启用。WSL、SSH 和未注册子代理不获得本机桌面能力。

组件从当前程序目录加载。安装位置变化后，准备会话时会检查并修复 MyCodex 内置插件的旧路径注册。若仍不可用，先查看活动区的具体原因并检查插件是否启用；组件缺失或损坏时重新安装 MyCodex。普通对话仍可继续。

应用授权沿用现有审批界面，按官方提供的范围选择本次、本会话或始终允许此应用。完全访问只对符合现有规则的普通权限自动本次允许。“只读”是文件沙箱权限，不表示所有桌面操作都只读；切换权限档位也不会撤销以前明确保存的应用授权。

多个会话或 MyCodex 实例同时操作桌面时，只允许一个回合占用，其他请求会提示忙碌。点击停止、结束回合、重连或退出所属目标会清理相应操作；发生故障后不会自动重放输入，请在新的有效回合中继续。

十一、运行时、配置和本地数据保存位置

MyCodex 的本地数据统一保存在：

  • %LOCALAPPDATA%\MyCodex

主要目录如下：

  • %LOCALAPPDATA%\MyCodex\targets\catalog.json：目标清单和上次主动选择的目标
  • %LOCALAPPDATA%\MyCodex\targets\<目标 ID>\config：该目标的设置、保留状态、自动化及手机身份
  • %LOCALAPPDATA%\MyCodex\targets\<目标 ID>\logs、temp、automations：该目标的日志、临时文件及自动化辅助数据
  • %LOCALAPPDATA%\MyCodex\config\relay-service.json：所有目标共用的手机连接设置
  • %LOCALAPPDATA%\MyCodex\migration-backup：升级前 MyCodex 文件的保留备份

开发版将目录中的 MyCodex 换为 MyCodex-Dev。目标 ID 不随改名变化。数据升级失败会保留旧文件并提供重试，请不要通过删除原数据绕过错误。

上述目标目录保存 MyCodex 的界面设置和工作状态。当前生效的认证、模型、Plugin、Skill、MCP 和会话保存在目标的 Codex Home；认证中心还会在对应环境保留供应商配置和已保存账号。Windows 认证后台的数据位于 %LOCALAPPDATA%\MyCodex\auth-core 下，按 Codex Home 区分，正式版和开发版使用同一 Codex Home 时会共用这份数据。不要把这些目录当作普通缓存删除或分享。

随程序分发的运行时组件位于 MyCodex 程序目录下，例如：

  • 程序目录\runtime\codex
  • 程序目录\runtime\putty：SSH 密码连接组件
  • 程序目录\runtime\auth-core：Windows 认证后台
  • 程序目录\runtime\cua：Computer Use 组件
  • 程序目录\runtime\git：Windows 内置 Git
  • 程序目录\runtime\relay：手机连接服务

如果内置 Codex 运行时被删除或损坏，可在目标管理器中编辑 本机 重新下载，或选择系统、自定义方式，也可重新安装 MyCodex 或打开已配置的 WSL/SSH 目标。使用 SSH 密码连接还需要程序附带的 Plink；缺失时请重新安装 MyCodex。

目标管理器... 打开后直接聚焦目标列表。选择、Enter 和双击不会打开目标，请使用明确的新增、编辑、移除、刷新和关闭操作。新安装首次进入本机，后续普通启动进入上次从菜单主动选择的目标，不恢复全部窗口。

Windows 只有一个目标，编辑本机时可选择：

  • 内置：推荐默认项，使用程序自带的 Windows Codex 运行时。
  • 系统：使用 Windows 系统路径中可直接执行的 codex。
  • 自定义：选择指定位置的 codex.exe 或 codex.cmd。

每个 WSL 发行版和 SSH 配置分别成为目标，新增、检测并保存后从目标菜单打开。新目标默认未设置隐显热键、关闭自动朗读和手机连接。修改运行中目标的启动参数时，确认后仅重连该目标；取消保留编辑内容。改名保留数据和原配对。

WSL、SSH 目标可以 移除，本机不能移除。确认默认选择取消；运行中的目标先保存并正常退出，取消或保存失败会保留目标。移除只清理该目标的 MyCodex 本地设置和手机访问，保留项目、Git 仓库、远端 Codex 数据及办公文档；手机上的旧设备条目需手动删除。中继撤销或本地文件清理未完成时，状态会说明剩余情况，保留的移除归档不会重新成为活动目标。发现不认识的本地文件或与项目目录重叠时，会阻止移除并要求检查。

本机使用内置 Codex 时，启动会静默检查更新；保存切回内置运行时后，也会在连接前检查一次。检查失败或没有新版时，照常启动，不弹出提示。发现新版后会先询问是否更新；选择“否”将继续使用现有运行时，选择“是”才开始下载，并用模态窗口中的标准进度条显示进度。更新过程中可取消并返回客户端，继续使用现有运行时；更新成功后会弹框提示已安装的版本，连接成功后自动清理不用的旧版本；以后启动连接时也会补做清理。更新失败时可以重试或取消。系统、自定义、WSL 和 SSH 运行时分别管理。下载完成会校验完整性，其他目标继续使用原来的运行时，清理旧版本时也会保留仍在使用的版本。

选项中的语言、主题、声音、读屏、权限和办公设置也都属于当前目标，不会覆盖其他目标。

2. Windows Sandbox 运行时配置

从本机窗口打开目标管理器并编辑 本机，可检测和配置其内置运行时的 Windows Sandbox。

  • 检测：读取当前 Windows Sandbox 就绪状态。
  • 配置...：在状态为未配置或需要更新时可用，执行前会二次确认。
  • 如果刚切换运行时来源但尚未保存，Sandbox 检测和配置会要求先保存并重启 App Server，避免检查到旧运行时状态。

3. WSL 运行时怎么配置

使用 WSL 前，请先确认：

  • Windows 已安装 WSL。
  • 已经安装一个发行版，例如 Ubuntu。
  • 在 WSL 中可以执行 codex --version。
  • WSL 使用该发行版环境选择的官方 Codex Home，不继承或映射 Windows 的认证状态。需要 OpenAI 认证时，可在 MyCodex 登录引导中使用浏览器、设备代码或 API Key，也可以先在该 WSL 环境中使用官方 Codex 工具登录。
  • 如果 WSL 已由外部工具配置第三方模型服务，确认它在同一 WSL 发行版中可用；MyCodex 不复制 Windows 中的设置或密钥。

推荐设置步骤：

  1. 打开 设置 -> 目标 -> 目标管理器...。
  2. 选择 新增 WSL，或编辑已有 WSL 目标。
  3. 发行版填写你的 WSL 名称，例如 Ubuntu。
  4. Codex 命令通常保持 codex。
  5. Shell 通常保持 /bin/sh；如果你明确需要，也可以改成 bash 或其他 shell。
  6. 按 检测 WSL Codex，确认 WSL 内 Codex 可用。
  7. 保存后从目标菜单选择其名称打开；修改已运行目标的启动参数时可能需要确认重连。

WSL 模式下，MyCodex 的窗口、工作区列表、会话列表仍然在 Windows 图形界面中显示；真正处理请求、执行命令和读写工作区内容的是 WSL 内的 Codex App Server。

4. WSL 模式下的工作区路径

WSL 模式下推荐使用 WSL 能直接访问的项目目录。Windows 磁盘上的项目可以通过 WSL 挂载路径访问，例如 Windows 路径：

  • E:\Projects\demo

对应到 WSL 中通常是：

  • /mnt/e/Projects/demo

打开 WSL 工作区时，MyCodex 会显示运行时文件浏览器，可选择或输入绝对 WSL 路径，例如 /home/user/repo 或 /mnt/e/Projects/demo。不建议把 \\wsl$ 路径作为普通 Windows 工作区使用。

5. WSL 模式下的 Codex Home

WSL 运行时使用该发行版自己的 Codex 登录、配置和历史：

  • 如果你在 WSL 中自行指定了 Codex Home，MyCodex 会继续使用该位置。
  • 没有自行指定时，通常使用该发行版中的 ~/.codex。

Windows 和每个 WSL 发行版的登录、配置、历史、Plugin、Skill 和 MCP 状态相互独立；如需迁移内容，请使用相应工具或明确的导入流程。

6. WSL 模式下的命令和文件

WSL 运行时启用后，终端窗口里的独立命令会通过 WSL 中配置的 shell 执行。例如 pwd 返回的是 WSL 路径，ls、git status 等命令也按 Linux 语义运行。

如果工作区位于 Windows 磁盘上，WSL 通常可以通过 /mnt/c、/mnt/d、/mnt/e 等路径访问。命令仍按 WSL 环境的规则执行。

7. 远程 Unix（SSH）运行时

远程 Unix 模式适合把 Codex App Server、工作区、历史会话、技能、插件和 MCP 都放在远端 macOS 或 Linux 主机上运行。Windows 端只保留 MyCodex 图形界面。

  • 远端主机需要能执行 codex --version。登录、模型、历史、Plugin、Skill 和 MCP 都使用远端主机自己的 Codex 数据，不会从 Windows 复制。
  • 打开 设置 -> 目标 -> 目标管理器...，选择 新增 SSH，填写名称、主机、端口、用户名、Shell 和 Codex 命令。
  • 认证方式可选择 SSH 私钥或密码。私钥方式最稳定；密码方式使用随 MyCodex 打包的 Plink 运行时，首次连接可能需要根据检测提示信任远端主机密钥。
  • 检测通过后保存，再从目标菜单打开；更换 SSH 主机或用户请新建目标。
  • 远程工作区必须选择或输入远端主机上的绝对 Unix 路径，例如 /Users/name/repo 或 /home/name/repo。

切换编程/办公标签页、打开其他目标或切换手机设备都不会停止其他目标的工作。修改启动参数后重连只影响对应目标。连接失败由该目标自己的窗口显示，不会把工作静默转到本机。

在主窗口按 Alt+F4、使用 文件 -> 退出 或其托盘退出操作，只退出该目标。确认显示目标名称，默认选择 否，并统一提示编程与办公模式中的活动响应、命令和自动化。停止工作之前先保存草稿并处理未保存文件；取消或保存失败会保留运行。成功后关闭该目标的关联窗口、托盘图标和热键。关闭辅助窗口仍只关闭自身。

文件 -> 退出此版本的全部目标... 和托盘同名操作会列出本版本全部运行目标，包含隐藏窗口。全部目标先准备并保存，之后才开始停止工作；取消、保存失败或运行目标范围改变都会取消准备。若有目标未确认取消，请检查其窗口；无人继续协调的退出准备会在十分钟内解除。开始退出后，已经关闭的目标不会重新打开；对仍在运行或无法核验退出的目标，窗口提供 继续等待 和 返回仍在运行的窗口，不会强制结束进程。

十二、最推荐记住的快捷键

  • Ctrl+1：切换到编程标签页
  • Ctrl+2：切换到办公标签页
  • Ctrl+Tab / Ctrl+Shift+Tab：切换到下一个或上一个模式标签页
  • Alt+1：编程模式跳到工作区；办公模式跳到会话
  • Alt+2：跳到会话
  • Alt+M：跳到消息列表
  • Ctrl+F：查找当前消息
  • F3：查找下一个匹配
  • Shift+F3：查找上一个匹配
  • Left：在消息列表中跳到上一轮提问
  • Right：在消息列表中跳到下一轮提问
  • Ctrl+Up / Ctrl+Down：在消息列表中只移动焦点，不改变已有选择
  • Alt+I：跳到输入框
  • Alt+L：跳到活动区
  • Alt+K：打开终端
  • Alt+Q：停止当前响应
  • Ctrl+Enter：在输入框中发送消息；焦点位于会话列表时在独立窗口打开当前会话
  • Ctrl+W：关闭独立会话窗口
  • 目标隐显热键：本机默认 Shift+Alt+M，新目标未设置；在各目标的 设置 -> 选项... -> 界面 中分别设置固定组合。热键只显示或隐藏所属的运行窗口，不启动未运行目标；冲突会提示，替换失败保留原有效热键。隐藏不切换模式或停止工作，也不隐藏独立会话窗口
  • Alt+Delete：在消息、终端和活动之间切换手动朗读目标
  • Enter：在子代理窗口的子代理列表中打开当前子代理
  • Delete：在子代理列表或待发送项目列表中删除当前项
  • Ctrl+Delete：在子代理列表中删除全部子代理
  • Esc：启用对应选项时隐藏主窗口到托盘或关闭独立会话窗口；消息查看器等其他对话框仍按各自规则关闭

十三、碰到问题时先看什么

如果只是想快速判断是不是入口用错了，可以优先检查：

  • 当前有没有先打开工作区
  • 当前工作区路径是否还存在
  • 如果登录引导已经出现，是否完成了 ChatGPT 浏览器、设备代码或 API Key 登录；如果使用第三方模型服务，确认它在当前目标中可以正常使用
  • 当前工作区下是否还没有会话
  • 如果看不到子代理，打开 查看子代理... 并按 F5。主会话已有线程 ID 时即可打开，即使尚未发现子代理；同时核对当前目标、父会话及连接状态。
  • 终端窗口或活动区是否已经给出更具体的错误信息

如果问题和运行时有关，优先检查：

  • 在 设置 -> 目标 -> 目标管理器... 中编辑对应目标，检查并检测其启动设置。
  • 如果选择 内置，确认程序目录下的 runtime\codex 是否还存在；如果缺失，可重新安装 MyCodex，或在运行时设置中重新下载所需版本。
  • 如果 Windows Sandbox 功能不可用，在本机窗口的目标管理器中编辑本机并检测 Windows Sandbox；如果刚修改运行时方式，先保存并重连该目标后再检测。
  • 如果选择 系统，Windows 命令行里是否可以直接执行 codex --version。
  • 如果选择 自定义，指定的 codex.exe 或 codex.cmd 路径是否仍然存在。
  • 如果选择 WSL，是否能在 WSL 中执行 codex --version，并且设置页中的 检测 WSL Codex 能通过。
  • WSL 模式下如果要打开 Windows 磁盘上的项目，确认路径是否能映射到 WSL 挂载路径，例如 E:\Projects\demo 对应 /mnt/e/Projects/demo；如果项目在 WSL 自己的文件系统中，则使用 /home/name/repo 这类绝对 WSL 路径。
  • WSL 模式下如果历史会话没有出现，确认历史是否位于当前 WSL 发行版使用的 Codex Home 中，而不是 Windows 的 Codex Home。
  • 如果选择 远程 Unix（SSH），确认远端主机可访问、SSH 主机/端口/用户名正确，私钥路径存在或密码已填写，并且设置页中的远程检测可以通过。
  • 远程 Unix 模式下如果 ChatGPT 账号或历史不符合预期，优先确认远端主机自己的 Codex Home 中是否已经完成登录；此模式不会读取本机 Windows 的 ChatGPT 账号和历史。
  • 远程 Unix 模式下如果模型或第三方模型服务不符合预期，检查远端主机自己的 Codex 配置，并在修改后重新启动目标。
  • 内置手机连接服务无法启动时，确认 程序目录\runtime\relay\mycodex-relay.exe 是否存在。使用公网服务时，在连接设置中检测服务器，并检查地址、TLS、租户 ID 和访问密钥。
  • 浏览器没有自动打开或无法回调时，可改用设备代码登录，按窗口显示的地址和代码继续；等待、成功、取消或失败信息会显示在状态区，可用读屏按需查看。
  • 认证中心提示配置已应用但未连接时，使用 重试连接；提示后台过旧时按界面更新。统一历史迁移未完成时，关闭其他 Codex 客户端后使用 重试迁移会话。
  • Computer Use 不可用时，检查插件启用状态及活动区错误，并确认程序目录中的 runtime\cua 完整。无需为了使用它安装官方桌面客户端。
  • 外部工具修改登录、模型、Plugin、Skill 或 MCP 配置后，普通自动重连不会应用这些变更；等待下一次正常启动目标，或在 Windows 目标使用 文件 -> 重载目标。

如果问题和 Git 工作台有关，优先检查：

  • 当前工作区是否是 Git 仓库；如果不是，可在 Git 工作台中执行 初始化仓库。
  • 先在 Git -> Git 环境 中检查实际使用的 Git。Windows 安装包自带 Git，外部终端找不到全局 Git 不代表 MyCodex 不可用；WSL 和 SSH 则需要在所属环境中能执行 git --version。
  • 推送、拉取或获取远端失败时，先查看 Git 工作台底部的最近输出。MyCodex 会尽量隐藏令牌、网址用户名和密码等敏感信息。
  • 推送需要 upstream；没有 upstream 时可按提示设置 upstream 后推送。
  • 回滚后普通推送被拒绝通常是 non-fast-forward，确认要改写远端历史时再使用强制推送。
  • 存在冲突时，提交和推送会被禁用；先在编辑器或命令行解决冲突，再回到工作台刷新。
  • 如果 Git 工作台提示仓库受保护或所有权不安全，通常是 Git 的 safe.directory 保护。确认仓库可信后，按 Git 错误提示把该目录加入 safe.directory。
  • 如果 GitHub 相关窗体中没有加载出登录状态或仓库列表，先确认同一环境里 gh --version 可以执行，并且 gh auth status 显示已登录。WSL 或远程 Unix 模式会使用对应环境中的 gh。
  • 如果删除 GitHub 仓库提示缺少 delete_repo 权限，可按错误提示运行 gh auth refresh -s delete_repo 后重试。
  • 如果 SSH 克隆或推送失败，确认公钥已经加到 GitHub，且当前机器上存在与之对应的私钥。

如果问题和朗读有关，优先检查：

  • 是否已经开启自动朗读
  • 当前手动朗读目标是不是你想要的 消息、终端 或 活动
  • 本机读屏服务是否可用
