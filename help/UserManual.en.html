MyCodex User Manual

This guide covers the main workflow, Office Mode, automations, online updates, Authentication Center, unified session history, targets, phone connection and pairing, accessibility, independent conversation windows, attachments, file management, subagent management, message browsing, import and sync, extensions, and target options.

1. Before You Start

MyCodex uses the included Codex runtime by default. In most cases it is ready after startup, and you do not need to download Codex CLI yourself.

Use Settings -> Targets to open or activate a configured target in its own window. For configuration, open Target Manager...; edit This PC to choose a Windows runtime, or add a WSL or SSH target:

  • Bundled: the default option. It uses the Windows Codex runtime packaged with MyCodex.
  • System: use a codex command already available on the Windows PATH.
  • Custom: choose a local codex.exe or codex.cmd.
  • WSL: keep the Windows UI and run Codex inside a WSL distribution.
  • Remote Unix (SSH): keep the Windows UI and run Codex on a remote macOS or Linux host over SSH.

WSL mode is useful when you want Linux tooling for a project, or when you want to avoid Windows command-environment encoding issues with non-English files. MyCodex does not install WSL or Codex inside WSL automatically. Prepare your WSL distribution and make sure Codex can run there before using this mode.

Each Execution Target uses its own Codex sign-in, settings, and history. Windows, each WSL distribution, and each Remote SSH target are independent, and MyCodex does not copy sign-in or settings between them.

After another tool changes Codex settings, the changes take effect the next time the target starts. On Windows, you can also use File -> Reload Target to apply them immediately. Ordinary automatic reconnect does not apply these changes.

2. First-Time Setup

  1. Start MyCodex.
  2. In most cases, you do not need to change runtime settings. MyCodex uses the bundled runtime by default.
  3. If you want to use WSL, open Settings -> Targets -> Target Manager..., choose Add WSL, detect and save the target, then open it from the Targets menu.
  4. When a Windows target needs sign-in, Authentication Center opens automatically. Choose Add, select a ChatGPT account configuration, and complete browser or device-code sign-in, or use a saved account. Save the configuration, then press Enter on its list row or choose Enable from the context menu.
  5. For API access, add an official or third-party configuration in Authentication Center, enter its address, key, and model, then save and enable it. The authentication backend retains configurations and credentials for later switching; protect the target data.
  6. WSL and SSH targets still show the official sign-in guide when required, supporting browser, device-code, or API-key sign-in. You can also open Account -> Authentication Center… to manage that environment. Use a device code when browser callbacks are unavailable.
  7. If the current target already has a working third-party model service, it can be used without a ChatGPT account and MyCodex does not request sign-in again.
  8. Back in MyCodex, click New Workspace.
  9. Select your project folder.
  10. If no session exists yet, click New Session, or type and send directly to auto-create one.
  11. Press Alt+I to jump to the input box.
  12. Enter your request.
  13. Press Ctrl+Enter to send.
Notes
  • If you see “Please open a workspace first”, the project folder is not selected yet.
  • If you see “No sessions in current workspace”, this is normal for a new workspace.
  • If an older session cannot continue, follow the on-screen prompt to refresh or try again.

3. Main UI Overview

  • Left: workspaces and sessions.
  • Center: message list, input area, pending items.
  • Right: activity area and terminal entry.

The right-side Activity area shows task progress and important status, including plans, reasoning snippets, tool activity, network requests, and changed files. When the current target provides usage information, the completion summary also shows current-turn and total usage. See the separate terminal window for detailed command output.

You can right-click the activity area to toggle Show Log. When it is off, the summary remains visible and only the log section is hidden. To clear existing log text, right-click and choose Clear Log.

The Terminal button opens a standalone command terminal window. The terminal can open even when no command is running. Use the bottom standard input box to run commands such as ping 127.0.0.1, git status, or a project build script.

Commands follow the current runtime target: Windows uses a Windows command environment, WSL uses its configured Linux shell, and Remote Unix uses the shell on the remote host.

The terminal keeps the current command and its output. New background output does not open the terminal or steal focus.

4. Common Operations

The message-list Review... action offers uncommitted changes, a base branch, a commit, and custom instructions. Enter the required branch name, commit hash, or instructions. Review uses the selected session's workspace and records the target and review configuration; these configured values are not a report of the actual executing model. Uncommitted changes and a new session are the defaults. MyCodex creates a new thread with the effective directory, model, reasoning effort and permissions, verifies the settings, then starts official inline review in that thread. The source conversation and its history are unchanged and are not copied. If the new thread is created but review fails to start, the session remains available in the list.

The message-list Fork menu creates an independent full fork or a fork through a selected finished turn, including that turn and excluding later turns. Turn forks require native runtime support; older runtimes can still create full forks. The new session keeps the source session's model and reasoning overrides, including following defaults. If saving the remote title fails, the new session remains available and a warning identifies it.

4.1 Send Message

  • Alt+I: focus input box.
  • Ctrl+Enter: send by default; Enter inserts a new line.

Under Settings -> Options... -> Appearance, Send message shortcut can swap the roles of Enter and Ctrl+Enter. You can also choose whether follow-up messages sent while working steer the active turn or are queued.

For asynchronous supplemental questions, the Pending Questions window lets you choose a suggested answer or select Other (enter your own answer). Other requires a non-empty answer before sending; a preselected choice is not submitted automatically. Answer later hides the window and retains unsent answers.

4.2 Plan Mode

Plan mode is useful when you want Codex to produce an implementation plan first, then let you decide whether to execute it. It is a per-session switch and does not affect other sessions.

  • Open the message-list context menu and choose Plan Mode to enable or disable it for the current session.
  • You can also send /plan from the input box to enable plan mode, or send /plan your request to request a plan directly.
  • After a plan is generated, MyCodex asks whether to execute it. If you accept, it switches back to normal execution mode and sends the execution prompt.
  • The current session's plan-mode state is the checked state of Plan Mode in the message-list context menu.

4.3 New Workspace and Session

  • New Workspace: choose a project folder.
  • New Session: create a new conversation under the current workspace.

If no session exists, sending directly from input also creates one automatically.

4.3.1 Office Mode

Coding and Office are two accessible tabs in the same main window. Office Mode is for everyday document work such as Word, Excel, and PowerPoint files, while Coding Mode keeps the project-oriented workflow. The default startup mode chooses which tab receives focus when MyCodex starts; it does not disable the other tab.

  • Select the tabs directly, press Ctrl+1 for Coding or Ctrl+2 for Office, use Ctrl+Tab/Ctrl+Shift+Tab, or use the dynamic command in the File menu.
  • Switching tabs changes only what is visible. Responses, commands, detached workbenches, and automations in the other tab continue running.
  • Office Mode follows the active Windows, WSL, or Remote Unix (SSH) runtime. Windows defaults to Documents\MyCodex-office; WSL and SSH targets default to $HOME/MyCodex-office.
  • Open Settings -> Options... -> Office to view the current runtime and customize only that target's Office directory. Windows, each WSL distribution, and each SSH profile keep independent settings and Office state.
  • Each runtime target has its own Office workspace. The left side shows the Office session list directly; subfolders under the Office directory are ordinary folders, not separate workspaces.
  • Unless you explicitly choose another location, generated documents, spreadsheets, presentations, images, and supporting files are saved in the current Office directory.
  • Clear, low-risk Office requests start directly. MyCodex uses enabled Skills, Plugins, MCP tools, or command-line tools that suit the task; no particular Office Plugin or OfficeCLI is required.
  • Before editing an existing file, MyCodex reads or inspects it. Unless you explicitly request an overwrite, it creates an edited copy and keeps the original. An explicit request to overwrite, replace, or save back to the original file is the authorization, so the same confirmation is not requested again. After creating or changing DOCX, XLSX, or PPTX files, MyCodex checks file validity and key content when possible, then reports the final file name and path.
  • Changing the Office directory does not discard existing Office sessions or move, copy, merge, or delete files in the old directory. Later work and deliverables use the new directory.
  • If a WSL or SSH home directory cannot currently be resolved, the Office tab remains available and reports that its directory is unavailable. MyCodex retains the Office workspace, conversations, and drafts and does not fall back to a Windows path.
  • OfficeCLI onboarding is an optional local Windows integration. It is offered only for a Windows runtime, never controls whether the Office tab is available, and is not required to complete Office tasks.

When deleting an Office conversation, MyCodex deletes the local history by default so old Office tasks do not accumulate. Confirm the conversation is no longer needed before deleting it.

4.3.2 Automations

Automations lets MyCodex run saved Codex instructions manually or on a schedule. It is useful for recurring tasks such as collecting news, reviewing a project, checking a workspace, or generating Office reports.

  • Open the top-level Automations menu to show the non-blocking Automations window. The main window remains usable while the automation window is open.
  • For either a Coding or Office session, use Create Automation on the session-list context menu to continue future automation runs from that conversation.
  • Use the workspace-list context menu Create Project Automation... in Coding Mode to bind an automation to a project workspace.
  • In the automation editor, set the name, type, schedule, model, reasoning effort, approval mode, and persistent prompt. Use Plugin and Skill to insert structured plugin and skill references.
  • Available schedules include manual-only, every few minutes, every few hours, daily, and weekly. Full cron expressions and worktree automations are not currently supported.
  • New automations are enabled by default. In the Automations tab, right-click an automation to edit, enable or disable, or delete it. Select an automation and press Run Now to start it immediately.

The Automations window has two tabs:

  • Automations: saved automation definitions, their enabled state, type, and next run time.
  • Run results: every recorded run, including running, completed, failed, canceled, skipped, waiting-for-approval, and waiting-for-input states.

Open a run result with Enter, double-click, or the Details button. The read-only details window shows the run name, status, times, model, workspace, related Messages, and Activity. Its buttons are Refresh, Open in main window, Open workspace, and Close. It does not include an input box, attachments, or a continue-conversation action.

Run results can be opened, stopped when still running, or deleted from the local automation result list. Deleting a run result uses a confirmation dialog similar to deleting a main-window conversation; when the run has related local conversation history, you can also choose to delete that local history. Deleting an automation also removes its local automation run results.

Review automation outcomes and items needing attention in the Automations window's Run results tab. Task status remains available in MyCodex without extra desktop notifications.

Automation model and reasoning-effort choices come from the current target. When an automation has no configured model, MyCodex uses a current available default. If a saved model is no longer available, the run selects an available model and shows both the configured and actual model in the run record. Automations still follow the selected approval mode and do not bypass permission prompts.

Keyboard basics: F5 refreshes the Automations window, Esc closes automation windows, and Enter opens the selected run result details.

4.4 Rename a Session Title

  • Select a session in the left list, then right-click and choose Rename Title...

Renaming a session in MyCodex updates the corresponding Codex conversation. If the same conversation is renamed in the official Codex app or another client, MyCodex shows the new title after the next synchronization. The title change updates the existing session only; it does not copy or create another conversation.

Session actions are available from the context menu in the left session list.

4.4.1 Conversation Statistics

Select a session in the left session list, right-click it, and choose Statistics... to view its title, model, reasoning effort, dates, activity, and available usage information. For older sessions or targets that do not provide usage, the window clearly says that the information is not available yet.

4.4.2 Subagent Sessions

When Codex creates subagents from a main session, MyCodex groups those subagents under the parent session instead of listing them as normal main sessions. A parent session with subagents is shown or announced with text such as 3 subagent(s) in the left session list.

To open subagents, select the parent session in the left session list, right-click it, and choose View Subagents.... The command is available once the session has a thread ID, including when no subagents have been discovered yet. Subagents open in a separate window, so the main window can stay on the parent conversation.

The subagent window has a subagent list on the left and the active subagent conversation on the right. Reading history does not resume the agent or change its configuration. Additional input uses the same thread and preserves its settings; running turns receive steering input. If the runtime state cannot be verified or the agent is not loaded, ask its parent to resume it and refresh. Drafts are kept separately while switching agents in the window.

  • Press Enter on a subagent, or double-click it, to load that subagent conversation.
  • Use Ctrl+Enter to send from the input box, or use the Send and Stop buttons.
  • Insert supports images, files, folders, and skills. You can also paste files or images with Ctrl+V in the input box.
  • After attachments are added, the Pending Items list appears. Press Delete on a pending item to remove it, or use the context menu to remove the selected item or clear all items.
  • In the subagent list, press Delete to delete the selected subagent, or Ctrl+Delete to delete all subagents. The context menu also provides Delete and Delete All.
  • Deletion is permanent. Confirmation lists the selected agents and their descendants, including archived descendants; active or unverified threads must be resolved first. Confirmed deletions remain applied if a later deletion fails.
  • Esc closes the subagent window without stopping the agents.

The subagent window is designed for keyboard and screen-reader use. Focus moves through the subagent list, message list, input box, pending items, and action buttons. The list includes all descendants and shows name, role, title, runtime status, agent-reported status, recent work, update time, and parent thread. Refresh runs every 5 seconds; press F5 to refresh immediately. The context menu opens the full recent work text.

4.4.3 Open a Session in an Independent Window

Both Coding and Office sessions can open in an independent window. Use this when you need to work with several conversations at once without changing the main window's current session. Select a session in the left session list, then choose Open in New Window from its context menu. With focus on the session list, Ctrl+Enter opens the selected session in the same way.

The independent window is a compact conversation workspace for that session. It includes the message list, input box, Insert and Send actions, activity list, terminal, Git Workbench, file browser, and subagent entry when the session has subagents. Its title combines the workspace name and session title, and it updates while that session is working.

  • An independent conversation window is not a third interaction mode. It keeps the session's original Coding or Office mode, workspace, and runtime. Opening the same session again activates its existing window instead of creating a duplicate.
  • The window is independent: using it does not block the main window, and changes to the same conversation continue to refresh in both places.
  • Its terminal, file browser, and Git Workbench use that session's workspace and active runtime. This also applies to WSL and Remote Unix (SSH) workspaces.
  • Press Ctrl+W to close the independent window. When Allow Esc to close the main and independent windows is enabled, which is the default, Esc closes an independent window and hides the main window to the notification area. Disable this option under Settings -> Options... -> Appearance when Esc should do neither.
  • A normal close saves any unsent draft. Reopening the same session restores the draft and, during the same MyCodex run, restores the message-list selection and manual Alt-browse position when the matching message is still available. These temporary browsing positions are cleared when the session is deleted or the App Server runtime target changes.

4.5 Terminal

  • Alt+K: open or activate the Terminal window.

The terminal can run system commands, build scripts, test commands, and Git commands directly. Preset commands are available from Common Commands in the terminal.

Typical built-in commands include build and Git Workbench quick entry.

Command presets are separated by target platform. Windows-only commands are not mixed into WSL mode by default. A command that works in both environments can be saved for both Windows and WSL. After selecting a preset, you can insert it into the terminal input box, or run it immediately when no command is active.

4.5.1 Git Workbench

The main Git Workbench entry opens the standalone Git Workbench. It does not block the main window, so you can inspect, commit, pull, push, and review the current workspace while continuing to use MyCodex.

  • The file list groups changes as Staged, Unstaged, Untracked, and Conflict.
  • Selecting a file only updates the diff view. It does not run a Git write operation. When focus moves to the diff box, MyCodex can load the current diff automatically if it has not been loaded yet.
  • File-level commands are in the file-list context menu, including Stage, Unstage, Discard Unstaged Changes, Delete Untracked File, Open File, Copy Path, and Copy Diff.
  • The bottom area supports commit title and detailed commit body, plus Commit, Fetch, Pull, and Push. If no upstream is configured, push asks whether to set upstream before pushing. You can also set or unset the current branch upstream from remote management.
  • Remotes management can list repository remotes, add a remote, edit a remote URL, remove a remote, copy remote names or URLs, and choose the remote name and whether to push immediately when publishing the current repository.
  • Branches and Commits combines branch navigation and commit history. The branch tree lists local and remote branches, and commit history can be loaded from the selected branch with Enter or the context menu.
  • The branch tree context menu dynamically shows actions for the selected item. It can switch local branches, create and switch to a local tracking branch from a remote branch, create a branch, delete or force-delete a local branch, delete a remote branch, rename branches, compare ahead/behind, view different commits, refresh branches, or load the selected branch history.
  • The commit history context menu can copy commit IDs, revert a commit, cherry-pick commits from another branch, amend the latest commit, or roll back to a selected commit. History-changing actions live in this history window instead of the Git Workbench main surface.
  • In-progress merge, rebase, and cherry-pick states are shown in Git Workbench. When there are uncommitted changes, conflicts, or unfinished Git operations, risky actions such as switching, deleting, merge, or rebase warn or block as appropriate.
  • Stashes saves, applies, pops, and drops stashes. After loading details, it shows the changed-file list and the full diff. Press Enter on a file or use its context menu to load a single-file diff, and copy the current diff when needed.
  • The worktree tree on the left lists Git worktrees for the current repository. Its context menu can create a new worktree, remove a worktree, prune stale worktree records, copy paths, and switch the current MyCodex workspace to another worktree.
  • Diagnostics and Maintenance opens one combined window. The Diagnostics tab is read-only and lists Git availability, repository state, remotes, upstream, HEAD, unfinished operations, working-tree status, object database statistics, and lock files, with suggestions in the details pane. The Maintenance tab provides repository integrity checks and official Git maintenance: Check Integrity runs the read-only git fsck --full, and Run Maintenance runs git maintenance run after confirmation.
  • When conflicts exist, commit and push are disabled. Use the conflicted file context menu to view conflict details.
  • If the current folder is not a Git repository, you can initialize it directly in Git Workbench.

When creating a Git worktree, MyCodex suggests a sibling folder, usually using the current workspace name plus -Worktree. You can change the location before confirming.

Git Workbench worktrees are for code workspace management.

The Windows installer includes Git, which local Git Workbench operations, cloning, and environment checks prefer. A global Git installation is not needed, and user and system PATH settings are unchanged. WSL and Remote Unix still use Git in their own environment. Configure credentials, SSH keys, and credential helpers in the relevant environment; MyCodex does not sign in for you.

Longer Git operations continue in the background and can be canceled. When command output is displayed, MyCodex hides URL credentials, GitHub tokens, and common access tokens where possible.

Discarding file changes, deleting untracked files, rollback, revert, and force push all ask for confirmation. Use force push only when you are sure you intend to rewrite remote branch history.

4.5.2 Git Hosting and Remote Repositories

The top-level Git menu now provides GitHub-oriented remote actions that are separate from the current-workspace Git Workbench.

  • Git Environment: checks whether git is available in the active runtime and shows key environment items such as user name, email, and credential helper.
  • Remote Credentials: shows the gh sign-in state and local SSH key information in one window. GitHub uses the gh account already signed in for the current environment.
  • Clone Repository: supports both manual Git URL input and a GitHub repository list loaded through gh. Manual and GitHub modes are separated by tabs.
  • Remote Repositories: opens a separate repository browser for the current GitHub account. The list can show repository name, visibility summary, description, language, default branch, and update time.
  • The repository-list context menu dynamically shows actions for the current repository state. You can create repositories, rename repositories, edit description and homepage, change visibility, archive, unarchive, or delete repositories. Deleting a repository requires two confirmations and entering the full owner/repo; if permission is missing, follow the GitHub CLI message to grant the delete_repo scope.
  • Press Enter or use the context menu on a repository to open a details window. Repository details can be read directly inside MyCodex, including overview, releases, issues, pull requests, contributors, discussions, branches, and tags.
  • The branch tab in repository details can copy branch names and commit SHAs, open branch pages, set the default branch, delete remote branches, and, when the current workspace remote points to this repository, fetch a remote branch and switch to it locally.
  • The pull request tab supports filtering open, closed, merged, and all PRs; filtering PRs authored by you, assigned to you, or requesting your review; creating a PR from the current branch; checking out a PR locally; opening or copying PR URLs; viewing discussions; adding comments; and closing or reopening PRs.
  • The issue tab supports filtering open, closed, and all issues; filtering issues assigned to you or created by you; creating issues; opening or copying issue URLs; viewing discussions; adding comments; and closing or reopening issues.
  • Create Repository is available from the remote repository window. For an existing local Git repository, Git Workbench can also guide you through publishing the current repository to GitHub and binding the remote.
  • GitHub Store opens from the Git menu. Use Search to find a specific repository and Rankings to browse suggested content.
  • The Search tab supports keyword, language, topic, result limit, and a clear Search button. Less common filters such as license, stars/forks/open-issues ranges, sorting, and public-only search expand through Show advanced filters. Changing advanced filters does not run a query automatically; click Search again to run the query.
  • The Rankings tab is for discovery and only keeps ranking type, language, result limit, and Refresh Ranking. Ranking presets include Trending, New Repositories, New Stars, New Forks, High Activity, Top Forks, Recent Created, and Recent Updated.
  • The result list shows repository, description, language, Stars, Forks, open issues, license, updated time, pushed time, and topics. Focus is preserved across refresh actions to avoid breaking the current selection flow.
  • On a selected market item, press Enter to open the repository page or use the context menu for dynamic actions: open repository page, copy HTTPS URL, copy full name, clone, fork-and-clone, and fetch/pull when the repository already exists locally.

GitHub sign-in, repository lists, and hosting management require a separately installed and signed-in gh CLI in the current environment; bundled Git does not include it. Without gh, you can still clone by entering a Git URL manually. Private repositories also require working credentials.

SSH is treated as the Git transport layer rather than a separate account system. You can keep using HTTPS through gh, or switch your Git remote URLs to SSH after you configure your key on GitHub.

4.6 Insert Images, Files, Folders, Plugins, and Skills

Click Insert near the input box to add image, file, folder, plugin, or skill items. You can also use Ctrl+V to paste files/images directly.

Every attachment is inserted at the current caret position as one indivisible attachment object on its own line. Arrow keys move across it as one position, and Backspace or Delete removes the whole attachment rather than a character inside its name. Screen-reader output at that position depends on the reader: it may be announced as an embedded object or as a blank, and the attachment name is not guaranteed. Use the pending-items list when you need to review attachment names reliably.

4.6.1 File Browser

When files can be browsed on the current target, the workspace context menu provides File Browser.... A Windows target shows local paths, a WSL target shows paths available inside WSL, and a Remote Unix target shows paths on the remote host.

The browser uses a Windows Explorer-style detailed list with Name, Modified, Type, and Size columns. Modified time is shown to the minute and refreshes when file information changes. Use Up and Down to move through items, and Left and Right to browse the columns for the current item.

The file browser supports Home, Up, Refresh, Search, New Folder, New File, Preview, Copy, Cut, Copy Path, Delete, and Attach. Use Ctrl+C or Ctrl+X to copy or cut selected entries, then use Ctrl+V in a destination folder to paste them. The same file-management flow applies to local Windows, WSL, and Remote Unix (SSH) file systems; a partially failed paste reports only the failed count so normal focus reading is not interrupted. You can type a path in the address box, search under the current path, and press Esc to leave search first or close the window when search is clear.

Opening a file follows its type. Known text files use the text preview or editor flow. Archives, executables, images, audio, video, and other non-text files use the Windows system default app when Windows can access the path directly, such as local paths or WSL mounted-drive paths like /mnt/c, /mnt/d, and /mnt/e. Non-text files under WSL-only paths such as /home/user/..., or on a remote SSH host, are not downloaded to a local temp folder automatically; that avoids opening a detached copy or accidentally executing a remote file locally.

Use Attach to add the selected runtime paths to the current message's pending items.

4.7 Import and Sync

Workspace migration actions are grouped under the workspace-list context menu Import & Sync:

  • Sync Thread History...: reads local history sessions from the current Codex Home that are not yet in MyCodex, then syncs them into the current workspace.
  • Import Other Sessions...: selects sessions from other workspaces or unassociated sessions and copies them into the current workspace as new sessions. This is a copy import: it does not move the source session, and deleting the imported session later does not delete the source session.
  • Import External Agent Config...: detects external agent configuration and lets you import selected user-configuration or current-workspace items.

Common keys in import and sync windows:

  • F5: reload the list.
  • Space: check or uncheck the current item.
  • Enter: import or sync the checked items.
  • Esc: close the window.

Import Other Sessions does not check list items by default. Select items explicitly before importing to avoid copying many sessions into the current workspace by accident. External-agent import also requires preview and explicit selection; broad configuration and unknown items are not imported, and MyCodex does not migrate external configuration in the background.

4.8 Authentication Center, Sign-In, and User Center

Open Account -> Authentication Center… to manage provider configurations and saved accounts for the current target. Check the target and Codex Home shown at the top before making changes. Windows, WSL, and SSH use their own environment's data; Authentication Center does not copy Windows credentials to other targets.

Authentication Center changes global settings in that Codex Home, which also affects Codex CLI and other clients using the same location. After connecting, MyCodex tries to recognize and capture the current configuration. Refresh Authentication Center to inspect external configuration changes; an existing chat connection still needs a target reload or normal restart to reread them.

  • Add: choose a preset or configuration type. Supported types include ChatGPT accounts, official OpenAI API, and third-party Responses, Chat Completions, and Anthropic Messages APIs. Enter the name, API base URL, and key as requested; some protocols require conversion by the authentication backend.
  • A ChatGPT configuration supports browser sign-in, device-code sign-in, or Use saved account. Successful sign-in saves the account; click Save in the provider window to finish the configuration. Signing in alone does not switch the active identity.
  • For API configurations, use Get models or Add model and choose a default model. MyCodex tries to fill blank context lengths and reasoning levels; review them before saving. Context and compaction provides the related settings supported by the backend.
  • Selecting a row does not switch providers. Press Enter or choose Enable from its context menu to apply it. Double-click or choose Edit to open its configuration. The context menu also offers copy, sign in again, and deletion of a non-current configuration.
  • Saving a new or inactive configuration does not switch the current provider. Editing the current configuration reads global settings; saving updates them immediately and attempts to reconnect. Active responses, commands, automations, and other work prevent configuration changes; finish that work before retrying.
  • Saved accounts lets you inspect and remove accounts. After deleting a provider configuration, check the result to see whether its account is still used by other configurations. Removing an account can also clear its matching global sign-in; configurations using it will need to sign in again.
  • If the configuration was applied but reconnection failed, use Retry connection. The global change is not rolled back automatically. Existing conversations may need a compatible model or a new conversation.

Edit provider TOML opens the configuration editor. A backend with full editing support shows the complete config.toml as it will be after switching to that provider. Provider fields are saved with the configuration; other changes are written to the global file when you click Save in the outer provider window. Saving inside the editor only updates the form. If another program changed the same fields, a conflict dialog lets you choose which values to keep or cancel. Configuration text can contain credentials; do not share it directly.

The Windows authentication backend is included with MyCodex. WSL and SSH Authentication Center checks and, when needed, deploys the matching backend components, requiring network access and permission to write to the target directory. Use Update backend when the interface reports a compatibility issue; reinstall MyCodex if local components are missing. For a configuration that requires protocol conversion, open MyCodex after a target restart to restore the service before using the CLI in that environment.

4.8.1 Unified Codex Session History

Unify Codex session history in Authentication Center is off by default and affects only the current execution target. When enabled, ChatGPT accounts and third-party providers share a session identity, allowing earlier conversations to continue with the configuration in use after switching.

  • Close other Codex clients first and review the session count in the confirmation dialog. Enabling moves earlier official sessions to the shared identity without copying their contents. Until you turn it off, the official ChatGPT client will no longer list those sessions; they remain visible in MyCodex.
  • Turning it off restores the previously moved official sessions and retains content added in the meantime. Shared sessions created while it was on keep their shared identity, can subsequently continue only through third-party providers, and are not listed by the official ChatGPT client.
  • If moving or restoring sessions did not finish, use Retry moving sessions. Do not delete history files to clear the pending state.
  • Before continuing another provider's conversation with ChatGPT, MyCodex removes incompatible content such as that provider's reasoning. If unreadable earlier compaction summaries also need replacement, a separate confirmation explains the loss of that earlier context for the model. A session backup is retained.

4.8.2 User Center and Official Settings

Account -> User Center is available for ChatGPT accounts and shows the account, plan, credits, rate limits, and usage. Missing information is reported explicitly. Reset quota is available only when the account supports it and asks for confirmation before running.

Settings -> Options... -> Official Settings edits supported user-level Codex runtime settings. Not having a ChatGPT account is not necessarily an error: a working third-party configuration can be used normally. After another tool changes sign-in or model settings, normally restart the target; Windows also offers File -> Reload Target. Ordinary automatic reconnect does not reread those external changes.

4.9 Check for Updates

MyCodex silently checks for app updates after startup. When a new version is available, it shows an update window with release notes in the current UI language.

  • You can also open Help -> Check for Updates... manually.
  • The release notes area is a standard text box and receives focus when the window opens, which makes it easier to read with a screen reader.
  • Choose Update Now to download the installer with progress. After download, review the running targets before confirming Exit all and install update. Every listed target must save and agree before shutdown starts; the installer waits until all affected processes have actually exited. Cancellation or an unverified remaining process prevents installation.
  • Only one update can use the same installation at a time. Another edition using its files must exit normally first; the update does not silently close that edition. A development window asks you to build and replace the development version instead of running the release installer.
  • Choose Ignore Update to skip the detected version. Later higher versions can still be shown.

4.10 Phone Connection and Pairing

Open Settings -> Phone Connection... in the target you want to access. Each target has its own phone-connection switch, identity, and paired devices. All targets use one common service address and port.

  • Use Connection Settings... in this window to choose the built-in service or a public service. These settings apply to all targets; applying changes lists affected targets and may reconnect their phone connections while desktop tasks continue.
  • Choose Generate Pairing Code to copy pairing information to the clipboard. Import it on the phone, then compare the six-digit verification code shown on both devices before choosing Allow. Use Reject for an unknown request, or Later when you want to review it from the device list.
  • Refresh the paired-device list when needed. Its context menu can review a pending request or remove a device and revoke its access to this target. Disabling one target's phone connection leaves other targets available.
  • For a public service, import the complete deployment JSON with Import Server Info, or enter the connection values in Connection Settings. Detect the service before applying. Keep access secrets private.
  • Add each target as a separate device on the phone. The phone connects to and monitors one target at a time. Browsing device details does not switch; use Check and Connect explicitly. A target that is not running cannot be started from the phone.
  • Switching saves each device's Coding and Office drafts and pages, closes the previous connection, then connects to the selected device. Desktop work on the previous target continues. Failure or cancellation attempts to restore the original connection; returning reloads history and pending requests.
  • Normal upgrades, target renaming, and restarts preserve the original pairing. Newly added targets require their own first pairing. Current Device Settings changes that target's default model, permissions, and supported Codex advanced settings.

4.11 Compact, Archive, and Restore Conversations

Use Compact Context from the message-list context menu to summarize a long conversation before continuing. This does not delete the conversation from the session list.

To put work aside, choose Archive from a workspace or session context menu. Use Restore Archived Threads... from the workspace context menu when you need an archived session again.

4.12 Official Voice Chat

Talk instead of typing in the current conversation. Voice comes from Codex official realtime voice: requests that need work are handed to Codex in this conversation, and the voice tells you the result.

  • Requirements: the local Windows target (WSL and remote SSH targets are not supported yet), sign-in with a ChatGPT account, and Codex runtime 0.163 or later. Otherwise the Start Voice Chat button is unavailable.
  • Choose Start Voice Chat next to the composer. Without a current conversation, a new one is created first. Choose Stop Voice Chat to end. Voice chat also stops when you switch conversations, hide the main window, or lose the connection to Codex.
  • The talk key is F8 by default and works only while the main window is in the foreground. By default you hold the key to talk and release it to send; the microphone is open only while you talk, with short tones when it opens and closes.
  • What you say and the voice's replies appear in the message list. Requests you type and send while voice chat is on are also passed to the voice, which answers aloud when the result is ready.
  • Tasks handed to Codex show only the task text in the message list, and are not repeated when they match what you just said. Reopening a conversation that used voice merges the spoken exchange back into its history in time order. A conversation that only chatted, without handing a task to Codex, no longer shows its spoken content after MyCodex restarts.
  • When system echo filtering is unavailable, the status bar says so. Screen reader speech may then be picked up as your words while you talk; pause reading or use headphones.

Open Settings -> Options... -> Voice Chat to adjust:

  • Talk key: F6, F7, F8, F9, F11 or F12. Talk mode: hold to talk and release to send, or press to talk and press again to send. Both apply as soon as you choose OK.
  • Voice, Speaking pace (official default or slightly faster) and Reply volume (original, 150% or 200%): apply the next time voice chat starts.
  • Try Voice: plays a sample sentence with the current choices without saving, and stops by itself when it finishes; press it again to stop early. The preview keeps the microphone off and leaves no conversation in the session list. It is unavailable while voice chat is on.

5. Message List and Search

The message list is a plain-text, keyboard-first list for quick browsing, multi-selection, manual screen-reader reading, and user-turn navigation.

List rows show short previews. Long logs or code may end with an ellipsis in the preview, but the original text is retained: accessible text, copying, manual reading, and the message viewer still use the full content. Press Enter to inspect the whole message. While browsing a selected message, refreshing unchanged content preserves the selection and browsing position.

  • Up / Down: move to the previous or next message and update the current selection.
  • Home / End: move to the first or last message.
  • Ctrl+Up / Ctrl+Down: move only the message-list focus without changing the existing selection. This is useful while browsing around a multi-selection.
  • Shift+Up / Shift+Down / Shift+Home / Shift+End: extend the message selection.
  • Ctrl+Shift+Home / Ctrl+Shift+End: extend the selection from the current position to the start or end.
  • Space or Ctrl+Space: toggle whether the focused message is selected.
  • Ctrl+A: select all messages.
  • Ctrl+C: copy the full text of the selected messages; when there is no multi-selection, it copies the focused message.
  • Left: jump to the previous user turn.
  • Right: jump to the next user turn.
  • Ctrl+F: find within current message list.
  • F3: find next match.
  • Shift+F3: find previous match.

Press Enter on the message list to open the current message in the structured viewer. The viewer avoids automatic line wrapping where possible, making it friendlier for screen-reader line navigation, code-copying, and link opening.

In the viewer, press Enter on a link to open it in the default browser, or on a code block or its copy line to copy the code. The Apps key opens the context menu for link and code actions; Esc closes the viewer. Message search stays within the current message list and does not reorder it.

6. Settings, Options, and Extensions

Common entries under Settings include:

  • Default Model and Default Permission: affect defaults for new sessions.
  • Permission modes include Read Only, Auto, Custom, and Full Access. Read Only starts in a read-only sandbox and asks before writes, deletes, network access, or expanded permissions. Auto allows normal workspace work and asks when extra permission is needed. Full Access skips approval prompts and has the highest risk. Custom starts from read-only access, then automatically allows the approval categories you select in Options.
  • Options...: groups Appearance, Permissions, Office, Sound, Screen Reader, and Official Settings.
  • Targets: open or activate a configured target, or open Target Manager... to add or edit WSL and SSH targets and configure This PC. Open Workspace follows this window's target; WSL and SSH use absolute paths in their own environment.
  • Both Coding and Office follow the active App Server runtime. Office directory overrides and retained Office state are isolated by Windows target, WSL distribution, or Remote Unix SSH profile; the Office page in Options edits only the currently active target.
  • Extensions: a submenu that groups Plugin Management..., Skills Management..., and MCP Management....

Options... applies to this window's target, including language, theme, the visibility shortcut, sound, screen reader, and permissions. Its pages are Appearance, Permissions, Office, Sound, Screen Reader, and Official Settings. Focus the shortcut field and press modifiers with another key; Tab and Shift+Tab move focus. The Office page edits this target's directory. Official Settings edits supported user-level Codex settings with confirmation; Follow Default removes that override. Custom permissions and command prefixes are also saved per target.

Custom command prefixes lets you add, edit, or delete commands that should be allowed in Custom mode, such as git status or npm test. A command must start with the saved prefix; this is not a keyword match. Keep prefixes narrow and predictable, and do not automatically allow broad shell commands, deletes, cleans, forced resets, or other destructive operations.

Approval prompts are queued and shown one at a time. Later requests wait until the current approval is resolved. Approval summaries try to use concise command text and file-change summaries so the request is easier to review. Remote/mobile approval dialogs use the same decisions, but do not display Windows desktop mnemonic suffixes.

When an MCP server requests additional input, the current tool call waits for an explicit response. MyCodex opens an MCP Request dialog for option or text questions, a confirmation dialog for yes/no requests, or a URL confirmation before opening a browser page. Submit the requested answer to continue, or cancel to reject the request; leaving only the status message unresolved keeps that MCP call waiting.

Default model, default permission, and other conversation preferences are scoped by Execution Target. A session can override Model or Permission from the session-list context menu, or use Reset to Defaults to return to target defaults. The lists show only models and reasoning levels available on the current target; an unavailable saved model blocks sending until you choose another model.

The extension management dialogs share the same keyboard-friendly pattern: the main list keeps the default focus, the filter box is earlier in the tab order, and pressing Enter on a selected row opens a separate details window.

  • Plugin Management...: split into Installed and Market tabs. Use Market to browse, search, and install Plugins. Use Installed to view, enable, disable, uninstall, or open an authorization page.
  • Plugin Management includes MyCodex Official Marketplace, where you can browse and install Plugins. Other third-party Marketplaces can be added from the same window; adding a Marketplace does not install its Plugins.
  • Lists refresh after an install or uninstall. If an external tool has just changed a Plugin, press Refresh to reload. A Plugin appearing in Market is not necessarily installed; use the Installed tab to check.
  • If a Plugin exposes an app connection page, use Open Auth on the Installed tab. Opening the page does not itself prove that authorization succeeded; complete the page's Manage or Connect flow. If no pending authorization entry remains, the Plugin may already be connected.
  • Skills Management...: shows Skills available on the current target and has no standalone Skill Marketplace. User and project Skills can be created, edited, or removed. Plugin, system, and admin Skills are read-only; a Skill bundled in a Plugin follows that Plugin's lifecycle.
  • MCP Management...: filter and inspect status, OAuth, tools, and resources, then use the available buttons for add, settings, login, enable, disable, and delete. Refresh or reload the target after another tool changes MCP configuration.

The Appearance page also offers Font size (restart required) at 100%, 125%, or 150%. Save and normally restart that target window to apply it. Session information order offers subagent count/time/title, title/time/subagent count, or title/subagent count/time. It changes the display and reading order within each session entry, not how sessions are sorted.

Official Computer Use

The local Windows x64 installer includes verified official Computer Use components and the matching Plugin; the official desktop client does not need to be installed or running. Components are stored beside MyCodex in runtime\cua. Check the Plugin under Settings -> Extensions -> Plugin Management...; a deliberately disabled Plugin is not enabled automatically. WSL, SSH, and unregistered subagents do not receive access to the local desktop.

Components load from the current application directory. After an installation moves, MyCodex checks and repairs the old registration for its bundled Plugin when preparing a conversation. If unavailable, inspect Activity for the specific reason and check whether the Plugin is enabled. Reinstall MyCodex if components are missing or damaged. Ordinary chat remains available.

App permissions use the existing approval dialog with the scopes provided by the official component: once, this conversation, or always for this app. Full Access automatically grants only the current request when it meets the existing ordinary-permission rules. Read Only describes the file sandbox, not a guarantee that every desktop action is read-only. Changing permission levels does not revoke previously saved app grants.

Only one turn may own the desktop across conversations and MyCodex instances; competing requests report that it is busy. Stopping, ending the turn, reconnecting its target, or exiting that target cleans up the corresponding operations. Failed input is never replayed automatically; continue in a new valid turn after recovery.

7. Runtime, Config, and Local Data

MyCodex local data is stored under:

  • %LOCALAPPDATA%\MyCodex

Main local directories:

  • %LOCALAPPDATA%\MyCodex\targets\catalog.json: configured targets and the last explicitly opened target.
  • %LOCALAPPDATA%\MyCodex\targets\<target ID>\config: this target's settings, retained state, automations, and phone identity.
  • %LOCALAPPDATA%\MyCodex\targets\<target ID>\logs, temp, and automations: target logs, temporary files, and automation support data.
  • %LOCALAPPDATA%\MyCodex\config\relay-service.json: common phone connection settings.
  • %LOCALAPPDATA%\MyCodex\migration-backup: preserved pre-upgrade MyCodex files.

The development edition uses MyCodex-Dev instead of MyCodex. Target IDs do not change when targets are renamed. An upgrade failure keeps the old files and offers retry; do not delete original data to bypass the error.

The target folders above store MyCodex interface settings and working state. Active authentication, models, Plugins, Skills, MCP, and conversations reside in the target's Codex Home. Authentication Center also retains provider configurations and saved accounts in the corresponding environment. On Windows, authentication data is under %LOCALAPPDATA%\MyCodex\auth-core, separated by Codex Home. Release and development editions using the same Codex Home share this data. Do not delete or share these folders as ordinary cache files.

Runtime components distributed with MyCodex are stored next to the executable, for example:

  • App directory\runtime\codex
  • App directory\runtime\putty: SSH password connection support
  • App directory\runtime\auth-core: Windows authentication backend
  • App directory\runtime\cua: Computer Use components
  • App directory\runtime\git: bundled Windows Git
  • App directory\runtime\relay: phone connection service

If the bundled Codex runtime is deleted or damaged, edit This PC in Target Manager to download it again or choose System or Custom. You can also reinstall MyCodex or use a configured WSL/SSH target. SSH password connections require the included Plink; reinstall MyCodex if it is missing.

7.1 Targets and Runtime Settings

Settings -> Targets lists configured names only. The check mark identifies this window's target; selecting another opens its independent window or activates its existing one. Other targets continue working. This PC keeps the original window-title format; other targets prefix their configured name on associated windows.

Target Manager... opens with focus on the target list. Selection, Enter, and double-click do not open a target. Use the explicit add, edit, remove, refresh, and close actions. A fresh install starts This PC; subsequent ordinary starts reopen the last target explicitly chosen from the menu, without restoring all windows.

There is one Windows target. Edit it to choose:

  • Bundled: recommended default. Uses the Windows Codex runtime packaged with MyCodex.
  • System: uses a codex command available on the Windows PATH.
  • Custom: chooses a specific codex.exe or codex.cmd.

Each WSL distribution and SSH profile is a separate target. Add one, test and save it, then open it from the Targets menu. New targets start with no visibility shortcut, automatic reading off, and phone connection off. Changing launch settings for a running target asks before reconnecting it; cancellation keeps the edit. Renaming keeps its data and pairing.

Remove is available for WSL and SSH targets; This PC cannot be removed. The confirmation defaults to Cancel. A running target must first save and exit normally; cancellation or a failed save leaves it available. Removal clears that target's MyCodex local settings and phone access, while keeping projects, Git repositories, remote Codex data, and Office documents. Remove its old device entry manually on the phone. If relay cleanup or local-file cleanup is incomplete, the status explains what remains; a retained removal archive is not an active target. Unexpected local files or overlapping project paths block removal for inspection.

When This PC uses built-in Codex, MyCodex checks for updates silently at startup. Saving a switch back to the built-in runtime also checks before connecting. A failed check or no newer version lets startup continue normally. When a newer version is found, MyCodex asks whether to update. Choose No to keep using the existing runtime; choose Yes to download it in a modal window with a standard progress bar. Cancel stops the update and returns to the client using the existing runtime. On success, a completion message shows the installed version. After connecting successfully, MyCodex removes unused older versions; startup connections also retry cleanup of any that remain. If the update fails, retry or cancel. System, custom, WSL and SSH runtimes are managed separately. Downloads are verified, and other targets keep running on their existing versions. Older versions still in use are preserved during cleanup.

7.2 Windows Sandbox Runtime Setup

Edit the current This PC target in Target Manager to access Windows Sandbox detection and setup for its bundled runtime.

  • Detect: reads the current Windows Sandbox readiness state.
  • Configure...: available when the state is not configured or update required; it asks for confirmation before running.
  • If you changed the runtime source but have not saved it yet, Sandbox detection and setup ask you to save and restart App Server first so the check uses the intended runtime.

7.3 Configure WSL Runtime

Before using WSL, check that:

  • WSL is installed on Windows.
  • A distribution such as Ubuntu is installed.
  • codex --version works inside WSL.
  • WSL uses the official Codex Home selected by that distribution and does not inherit or map Windows sign-in state. When sign-in is needed, use the MyCodex browser, device-code, or API-key flow, or sign in with an official Codex tool in that WSL environment.
  • If an external tool configured a third-party model service inside WSL, confirm that it works in the same distribution. MyCodex does not copy Windows settings or keys.

Recommended steps:

  1. Open Settings -> Targets -> Target Manager....
  2. Choose Add WSL, or edit an existing WSL target.
  3. Enter your distribution name, for example Ubuntu.
  4. Usually keep the Codex command as codex.
  5. Usually keep the shell as /bin/sh. Use bash or another shell only when you explicitly need it.
  6. Press Detect WSL Codex to confirm Codex is available inside WSL.
  7. Save, then select its name from the Targets menu to open it. Editing launch settings for an already running target may ask to reconnect it.

In WSL mode, the MyCodex window, workspace list, and session list still run in the Windows UI. The Codex App Server inside WSL handles requests, runs commands, and reads or writes workspace content.

7.4 Workspace Paths in WSL Mode

In WSL mode, use project folders that WSL can access directly. Projects on Windows drives can be reached through WSL mount paths. For example, the Windows path:

  • E:\Projects\demo

usually appears inside WSL as:

  • /mnt/e/Projects/demo

When opening a WSL workspace, MyCodex shows a runtime file browser where you can select or enter an absolute WSL path, such as /home/user/repo or /mnt/e/Projects/demo. Avoid using \\wsl$ paths as normal Windows workspaces.

7.5 Codex Home in WSL Mode

In WSL mode, the selected distribution uses its own Codex sign-in, settings, and history:

  • If you chose a Codex Home inside WSL, MyCodex continues to use that location.
  • Otherwise, the distribution normally uses ~/.codex.

Windows and each WSL distribution keep independent sign-in, settings, history, Plugins, Skills, and MCP. Use the relevant tool or an explicit import workflow if you need to move content between them.

7.6 Commands and Files in WSL Mode

When WSL runtime is active, standalone commands in the Terminal window run through the shell configured for WSL. For example, pwd returns a WSL path, and ls or git status uses Linux semantics.

If the workspace is on a Windows drive, WSL can normally access it through paths such as /mnt/c, /mnt/d, or /mnt/e. Commands still follow the rules of the WSL environment.

7.7 Remote Unix (SSH) Runtime

Remote Unix mode is intended for running Codex App Server, workspaces, history sessions, skills, plugins, and MCP on a remote macOS or Linux host. The Windows side only keeps the MyCodex UI.

  • The remote host must be able to run codex --version. Sign-in, models, history, Plugins, Skills, and MCP use that remote environment's own Codex state; MyCodex does not copy them from Windows.
  • Open Settings -> Targets -> Target Manager..., choose Add SSH, and enter a name, host, port, username, shell, and Codex command.
  • Authentication can use an SSH private key or password. Private key is the most stable option. Password mode uses the bundled Plink runtime; first connection may ask you to trust the remote host key based on the detection result.
  • Run detection before saving, then open the saved target from the Targets menu. Use a new target when replacing the SSH host or user.
  • Remote workspaces must be selected or entered as absolute Unix paths on the remote host, such as /Users/name/repo or /home/name/repo.

8. Accessibility and Keyboard Priority

MyCodex is optimized for keyboard and screen-reader workflows. Core operations are reachable from menu accelerators and logical focus order.

Each target can have its own fixed visibility shortcut under Settings -> Options... -> Appearance. This PC defaults to Shift+Alt+M; new targets start unassigned. A shortcut shows or hides its running target only and does not start a closed target. Conflicts are reported without taking another target's shortcut; a failed replacement keeps the original working shortcut. Hiding preserves Coding/Office work and focus. Each target also has its own tray icon labeled with its name and status.

When Allow Esc to close the main and independent windows is enabled, Esc hides the main window to the notification area or closes the active independent conversation window. Disabling the option leaves Esc inactive for those two window types without changing Esc behavior in other dialogs.

The standard mode tabs are keyboard reachable. Press Ctrl+1 for Coding, Ctrl+2 for Office, Ctrl+Tab for the next tab, or Ctrl+Shift+Tab for the previous tab. In Coding Mode, Alt+1 moves focus to the workspace list and Alt+2 moves focus to the session list. In Office Mode, both shortcuts move focus to the session list because the workspace list is hidden.

Switching between Coding and Office tabs, opening another target, or switching phone devices does not stop work in other targets. Reconnecting a target after a launch-setting change affects that target only. A connection failure is shown in its own window; work is not silently redirected to This PC.

Automatic reply reading is saved per target and continues while that target is in the background or tray, regardless of how many targets are open. Completion, approval, automation, and tray-hide events do not add desktop notifications or notification speech. Configured sound prompts remain available. New targets copy This PC's speech-channel name; an empty name uses MyCodex. You can change each target's channel afterward. Identical names share screen-reader settings and speech, so an explicit stop of that channel can affect other targets. Closing a target releases its speech connection without stopping the shared channel.

Closing a main window with Alt+F4, choosing File -> Exit, or using its tray exit action closes that target only. The confirmation names the target and defaults to No. It warns about active Coding and Office responses, commands, and automations together. Drafts and unsaved file choices are handled before work stops; cancellation or a failed save leaves the target running. A successful exit closes its associated windows and removes its tray icon and shortcut. Closing an auxiliary window still closes only that window.

File -> Exit all MyCodex targets... and the same tray command list the running targets in this edition, including hidden windows. All listed targets prepare and save before any is stopped. A cancellation, rejected save, or changed set of running targets cancels preparation. If a target does not confirm cancellation, inspect its window; an abandoned preparation expires within ten minutes. After shutdown starts, targets already closed stay closed; the dialog lists those still running or whose exit cannot be verified, with Continue waiting and Return to running windows. It does not force-kill them.

  • Do not trigger heavy operations on focus movement.
  • Use explicit actions (Enter, menu command, button) to execute tasks.
  • Use list-based navigation for read-heavy content.

Manual screen-reader browsing has three targets: Message, Terminal, and Activity. Press Alt+Delete to cycle through them; MyCodex announces the active target name after switching.

The same manual browsing keys work in each independent conversation window. Their message, terminal, and activity cursors are separate from the main window and from other independent windows, so browsing one conversation does not move another conversation's manual-reading position.

Long text is read in full. You can also review it with manual browsing or the structured message viewer.

When the target is Message, Alt+Up and Alt+Down read the previous or next message, Alt+Left and Alt+Right read the previous or next line inside the current manually read message, Alt+Home and Alt+End read the first or last message, Alt+PageUp and Alt+PageDown move by five messages, and Alt+Enter opens the message currently selected by manual reading.

When the target is Terminal, Alt+Up, Alt+Down, Alt+Home, Alt+End, Alt+PageUp, and Alt+PageDown read terminal output line by line without moving focus into the terminal content.

When the target is Activity, the same Alt+Up, Alt+Down, Alt+Home, Alt+End, Alt+PageUp, and Alt+PageDown keys read the right-side activity records, including current activity, summaries, and log items.

In the subagent window, Enter opens the selected subagent, Delete removes the selected subagent or pending item, and Ctrl+Delete deletes all subagents after confirmation.

10. Troubleshooting

  • If App Server disconnects, wait for automatic reconnect or trigger retry by the related action.
  • If a command cannot be stopped, check current permission mode and command support.
  • If attachments become unavailable, re-add them before sending.
  • If subagents are missing, open View Subagents... and press F5. Check the selected execution target and parent session; a disconnected target cannot provide current status.
  • If browser sign-in does not open or cannot return to the target, use device-code sign-in and follow the address and code shown in the window. Waiting, success, cancellation, and failure are available in the status area for screen-reader inspection.
  • If Authentication Center applied a configuration but could not reconnect, use Retry connection. Follow the update action if it reports an old backend. For incomplete unified-history migration, close other Codex clients and use Retry moving sessions.
  • If Computer Use is unavailable, check Plugin enablement, the Activity error, and whether runtime\cua in the application directory is intact. Installing the official desktop client is not needed.
  • If a third-party model service is configured, confirm it works on the selected target. A working third-party configuration does not require a ChatGPT account.
  • If runtime connection fails, edit that target in Settings -> Targets -> Target Manager... and test its settings.
  • If Bundled is selected, confirm App directory\runtime\codex still exists. Reinstall MyCodex or download the required runtime again if it is missing.
  • If Windows Sandbox features are unavailable, edit This PC in Target Manager and run Windows Sandbox detection. If you just changed the runtime source, save and reconnect that target before detecting.
  • If System is selected, confirm codex --version works in Windows Command Prompt or PowerShell.
  • If Custom is selected, confirm the configured codex.exe or codex.cmd still exists.
  • If WSL is selected, confirm codex --version works inside WSL and Detect WSL Codex passes in the settings window.
  • In WSL mode, if you want to open a project on a Windows drive, confirm the path can map to a WSL mount path, such as E:\Projects\demo to /mnt/e/Projects/demo. If the project is inside the WSL file system, use an absolute WSL path such as /home/name/repo.
  • If history sessions do not appear in WSL mode, check the Codex Home actually used by that distribution. MyCodex does not read Windows Codex history for a WSL target.
  • If Remote Unix (SSH) is selected, confirm the remote host is reachable, host/port/username are correct, the private key exists or password is entered, and remote detection passes in the settings window.
  • In Remote Unix mode, if the ChatGPT account or history looks wrong, check the remote host's own Codex Home. This mode does not read the local Windows ChatGPT account or history.
  • If a model or third-party model service looks wrong in Remote Unix mode, check the Codex settings on the remote host and restart the target after changing them.
  • After another tool changes sign-in, model, Plugin, Skill, or MCP configuration, automatic reconnect does not reload the change. Wait for the next normal target start, or use File -> Reload Target on Windows.
  • If the built-in phone service cannot start, confirm App directory\runtime\relay\mycodex-relay.exe exists. For a public service, run Detect Server in Connection Settings and verify its address, TLS setting, tenant ID, and access secret.
  • If Git Workbench says the workspace is not a Git repository, use Initialize in Git Workbench if this folder should become a repository.
  • For Git failures, use Git -> Git Environment to check the Git MyCodex uses. Windows includes its own Git; failure to find global Git in an external terminal does not prove MyCodex Git is unavailable. WSL and SSH still need git --version to work in their own environment.
  • If fetch, pull, or push fails, read the latest output at the bottom of Git Workbench. MyCodex hides common tokens and URL credentials where possible.
  • Push requires an upstream. If no upstream is configured, follow the prompt to set upstream before pushing.
  • If a normal push is rejected after rollback, it is usually non-fast-forward. Use force push only after confirming you intend to rewrite remote branch history.
  • If conflicts exist, commit and push are disabled. Resolve conflicts in your editor or command line, then refresh Git Workbench.
  • If Git Workbench shows a repository as unsafe or blocked by ownership protection, it is usually Git safe.directory. Follow the Git error message and add the repository to safe.directory if you trust it.
  • If GitHub-related windows are empty or unavailable, first confirm gh --version works in the same environment and that gh auth status reports a signed-in account. WSL and Remote Unix modes use gh from that environment.
  • If deleting a GitHub repository reports missing delete_repo permission, run gh auth refresh -s delete_repo as suggested by the error message, then retry.
  • If SSH cloning or pushing fails, confirm that your public key has been added to GitHub and that the corresponding private key is available on this machine.
